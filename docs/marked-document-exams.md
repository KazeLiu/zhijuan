# 按 ★ 和填空标记生成题库

## 先看来源，再开始生成

1. 在资料库上传保留原文编号、换行、`★` 和 `<答案>` 的资料。
2. 打开「题库 → AI 生成 → 按资料生成」，选择文件，将「资料规则」切换为「★ 与 <> 标记」。
3. 点击「解析来源」。此步骤只读取资料，不调用模型、不创建题目；展开来源，检查父级上下文、各小节的熟记标记和填空题数量。
4. 确认后选择难度，点击「生成并入库」。熟记内容中的填空由程序直接构造；判断、单选和多选逐题请求当前模型。每个完整来源默认处理全部原文填空，并分别尝试一道判断、单选、多选；内容不足时模型可以不出该题型。
5. 后续增加简单题或其他题型时，使用「定向补题」，选择带「【标记】」的已有来源。原文、层级与熟记要求直接复用，不再让模型重新划分全文。

普通资料模式保持原有全文梳理及逐题生成方式；原有场次 AI 出题入口保持不变。两种模式的来源目录分别保存，不自动重写已有题库分组、试卷或成绩。

## 父级熟记标记向下继承

例如：

```text
（一）定义
★ 5.示例对象包括<类型甲>、<类型乙>、<类型丙>。
（二）管理范围
6.本条描述另一项管理规则，未标记为熟记。
（三）操作要求
★ 检查项目包括：
（1）检查周期为<每月一次>。
（2）检查结果保留<一年>。
（3）发现异常应按规定报告。
```

- 第 5 条是一个熟记来源，生成一道带三个空的原文填空。
- 第 6 条是普通来源，仅生成判断和选择题。
- 「检查项目包括」及其三个子项作为一个完整来源保存；三个子项继承父级 `★`。第（1）、（2）项各生成一道填空，题干保留「操作要求／检查项目包括」的上下文；第（3）项没有指定填空位置，不额外挖空。
- 同一完整来源可以有多个候选题，一份试卷仍最多抽一道，避免父级条件与清单拆散后重复考查。

识别的层级包括「第×章／节」「一、」「（一）」「1.／1、」「（1）」及圈号；中英文括号均可使用。无编号但带 `★` 的条目也可作为父条目，单独一行的 `★` 作用于紧接的条目。熟记范围到同级或更高层级的新条目结束。`<>` 或 `＜＞` 的空位只属于所在小节，不向兄弟小节继承。

普通内容仅出判断、单选和多选。填空必须同时满足本节带有或继承 `★`、本节包含明确的 `<答案>`；AI 不能自行增加填空位置。熟记标签不自动规定每张试卷的重点占比。

## 补题、重复与失败

定向补题仍按选中范围的合计题量分配。指定填空时只分配给包含熟记填空位置的来源；所选来源都不支持填空时，创建任务前提示调整。自动题型模式在允许的题型中分配。

原文填空不会通过改难度或改写题干重复入库。指定位置已经全部生成时显示原因，不额外挖空补足数量。模型生成的判断和选择继续使用已有题目作为去重上下文，并执行原来的精确重复与答案冲突检查。

来源按原文范围稳定保存，标记模式只在引用范围完全一致时沿用已有分组，不把覆盖多个旧范围的新条目强行合并。相同范围确实存在多个人工分组时仍报告冲突，不自动改动旧题。

标记未配对、空答案或嵌套标记在解析预览时显示文件和定位。现有每空答案 20 字、题干 2000 字及引用长度限制继续生效；个别填空超过限制时记录到任务问题列表，继续其他题目。每道填空保存独立进度，失败项不会让后面的填空重复处理同一个位置；只有模型请求会自动尝试最多 3 次。

如果资料解析后已经丢失编号、换行或符号，需要先修正资料文本，再使用此模式。

## 数据与接口

新增迁移 `013-marked-source-rules`，只为 `bank_generation_sources` 追加可空的 `marked_rules_json`，保存各小节的上下文、原文和熟记状态。原始资料及引用不改写。迁移 011 的普通来源回填继续使用原查询，不依赖尚未增加的列。

- `POST /api/admin/question-bank/generation/preview`：请求 `{libraryFileIds:[...]}`，返回来源层级与填空题数量；要求管理员身份，不写数据库、不调用模型。
- `POST /api/admin/question-bank/generate`：资料模式新增可选 `documentMode: 'standard' | 'marked'`，省略时仍使用普通资料规则。
- 任务详情返回来源的 `markedRules`；来源目录以 `documentMode: 'marked'` 区分标记来源。定向补题接口继续使用原来的来源 ID 和题量参数。

部署此分支前备份数据，启动时执行新增迁移。
