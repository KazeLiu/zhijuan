# 填空答案纠错与批量重判

同一空位的标准答案为「优盘」，28 人填写「U盘」时，可以一次认可这 28 人的写法，无须逐份改分。

## 在场次内确认同义答案

1. 从「场次详情」或「成绩汇总」进入「填空答案纠错」。尚未结束的已发布场次先暂停；已结束场次可直接使用这个入口，普通题目结构仍保持锁定。
2. 在对应题目、空位下勾选认可的写法。系统按统一规范化后的内容归组，显示每种写法的涉及人数，可同时选择多种写法；原始作答保留。
3. 填写纠错原因。需要供后续组卷使用时，勾选「同步别名到题库」，默认不勾选。
4. 先预览：核对新增的可接受答案、受影响答卷、每个人自动总分与最终总分的前后变化、90 分及格状态，以及保留的人工复核项数。
5. 确认后，新增答案与本场自动分、最终总分、纠错记录在同一事务中保存。个人错题、团队错误率和成绩导出在下次读取时反映新结果。

人工复核分继续优先于自动分。自动分变化时，已有人工分对应的最终得分可以保持不变；一份答卷中其他题目仍可能改变总分。

## 统一填空比较规则

所有填空题统一进行 Unicode NFC、去两端空白、内部连续空白折叠为一个空格、小写比较。作答和每个可接受答案使用同一规则；保留内部单个空格、标点和单位，不做模糊匹配或交卷时的 AI 语义判分。

编辑器删除大小写开关，AI 输出固定不区分大小写。旧数据中的 `caseSensitive=true` 不再参与判分；字段继续保留，新增或修改的题目统一保存为 `false`。

历史已交卷分数不会仅因读取页面而改变。如果旧自动分与统一规则不一致，纠错页会显示待更新答卷数；不勾选新同义写法也可以预览并确认重判。迁移不会自动批量改写历史分数。

## 预览与记录跟随本次确认

修改勾选、原因或同步选项后，需要重新预览。预览保存题目版本、已交卷答卷版本和关联题库版本；预览后有新交卷、人工改分、题目修改或题库变化时，确认会要求重新预览。确认请求按预览 ID 幂等处理，不重复重判。

记录保留操作者、时间、原因、答案前后差异和逐人分数变化。页面展示最近 20 次已确认记录；完整记录保存在数据库。

同步题库只给明确关联且内容兼容的题库题追加别名，保留启停状态，不重写其他历史场次。未关联或源题已删除时，预览明确提示只修正本场；源题内容或标准答案已变化时，先核对或关闭同步选项。题库的可比统计仍按当前答案定义筛选关联答卷。

## 接口与升级

- `GET /api/admin/exams/:id/blank-corrections`：题目、空位、错误写法分组、待重判数量及记录。
- `POST /api/admin/exams/:id/blank-corrections/preview`：`BlankCorrectionInput`，只保存预览，不改题目或分数。
- `POST /api/admin/exams/:id/blank-corrections/apply`：`{previewId}`，重新核对版本后原子提交。

接口均需要管理员权限。页面不提供修改题型、题干、空位数量或任意替换标准答案的能力；已结束场次的锁定规则不变。

迁移 `012-blank-corrections` 仅增加预览与纠错记录表。更新后需重启服务应用迁移，升级前保留完整数据备份。本次只修改代码，未运行迁移、功能测试、应用或浏览器验证。
