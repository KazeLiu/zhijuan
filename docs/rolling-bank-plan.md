# 滚动出题与题库生成

## 本次实现

- 菜单「滚动出题」直接进入配置页，保存一套每日规则；默认北京时间每天 00:00 至次日 00:00，20 题（单选 10、多选 4、判断 4、填空 2），可修改。
- 启用后每天从题库组卷并自动发布为独立场次，手动场次不受影响。保存规则不修改已有试卷；暂停规则不结束已发布场次。
- 题库 AI 先通读全部所选资料，归纳知识点和每个知识点下的完整来源，再逐来源出题，不要求用户填写考点数量。一个来源可以有多种题型、同一种题型也可有多道题；每次模型调用只生成一道，保存后再出下一道，每个来源默认最多 6 道候选、无合适新题时提前停止，不限制整份资料的总题数。出试卷时才选择题型数量或手动选题。
- 同一来源的题目跨题型互斥，一份卷只选一道；同一知识点下的不同来源可以同时入卷。题库可编辑同源考点以合并分组。未归组的旧题仍各自独立。
- 题库「AI 生成」内提供「定向补题」，按知识点或来源选择，设置本次合计题量或各题型数量，沿用原来源分组，不重新阅读全文。来源独立保存，可长期选择；生成结果内的知识点与来源旁也可直接发起补题。
- 随机组卷统一匹配题型名额与考点组；滚动组卷优先使用未用过或最久未用的组。可用独立组不足时整次失败，不凑半卷。
- 菜单「错题集」显示已启用易错题，按错误率降序、作答人数降序、ID 升序排名。普通与滚动组卷可勾选「使用错题集」，默认从当前筛选范围内排名前 50 道中抽题，可修改范围；每日生成时按最新统计重新排名，范围内仍按原同源互斥和轮换规则抽取，不足不混入普通题。
- 取消审核状态和操作；保留启停。列表支持多选直接删除，题库改动不改历史试卷。

## 执行顺序

1. 增量迁移、共享类型：同源考点、试卷来源组快照、题库生成任务、滚动规则及每日记录。
2. 题库服务：分组互斥匹配、手动追加约束、直接删除与批量删除、AI 全文梳理及逐来源入库。
3. 滚动任务：按时区计算每日窗口；创建、组卷、发布在一个事务内完成；日期唯一约束防重复；失败保留原因，管理员修正后主动重试。服务启动只补当前仍有效的一天，不补历史过期试卷。
4. 管理页：滚动配置、今日状态与重试；AI 生成进度；题库多选删除、直接编辑与同源考点编辑。
5. 阅读调用链和差异自查，更新本文使用说明。本轮未新增或运行测试，未主动启动应用、浏览器或模型生成；真实模型批量生成由用户试用。

## 约束与失败处理

- 沿用单进程 SQLite、现有模型设置和后台执行器，不添加依赖；模型调用在事务外，写库前重新校验引用与重复。
- 滚动自动出题不调用 AI；AI 题库任务由管理员发起，每个模型请求最多尝试 3 次。出题请求仍失败时记录错误并继续后面的请求及来源，结束后弹出问题列表；全文梳理耗尽重试及配置、鉴权问题明确结束。
- 服务需持续运行才能按时生成；重启不会重复创建已成功的当日场次。滚动组卷失败后不自动反复执行，页面可重试。
- 数据库只追加迁移，不改旧迁移；升级前保留现有数据目录备份，降级应同时恢复升级前数据库和程序。
- 全文梳理必须逐段覆盖：每个编号段归入一个来源或记录忽略原因。带答案的原题和分行答案合为完整来源，缺答案的原题不补猜；PDF 整页先细分行、句，不能把一整页的多道原题当一个来源。遗漏或重复段编号时明确失败，不把抽样当作全文完成。
- 梳理结果和原文快照存入任务。每次请求的题目全部校验后，与该请求结果在同一事务提交。精确重复题不覆盖已有题，计入跳过数量；同源同题型的不同题目可以共存。后续失败保留已入库题，手动重试只执行失败及未处理请求，包括同一来源中先失败后成功的情况；梳理阶段失败则重新梳理。继续使用原任务参数，修改资料、难度或补充要求后应发起新任务。
- 定向补题合计 1–100 道、最多 100 个来源，题量轮流分配给选中来源，优先补已有题较少的来源。每次请求只出一道并独立保存进度，指定题型只发送该题型规则及示例；失败可从未完成请求继续，旧任务只拆分失败或未完成的题量。相同题目标准答案不同的结果不入库，页面展示冲突及新旧答案；精确重复另计跳过数。少出或跳过后显示实际入库与目标差额，不无限重试，也不替换已有题。

## 试用关注点

配置启用 → 今日独立场次 → 考生自选；AI 生成 → 变体同组 → 单卷不撞组；多选删除与历史试卷独立。每日场次与内网模型的使用效果继续由用户试用，题库生成的实测范围见下文。

## 页面与接口

- `/admin/rolling`：每日配置、题量预览、今日生成／失败重试与最近 14 次记录。未保存规则可以还原为最新服务端版本。
- `/admin/question-bank`：AI 生成、人工新增、点击题干编辑、当前页多选删除；同源考点可在编辑页调整。
- `GET /api/admin/rolling` 返回配置、版本、今日状态、最近记录、下次时间和已保存规则的可用量。
- `PUT /api/admin/rolling` 接收 `{ expectedVersion, config }`；首次版本为 0。`config` 含 `enabled`、`title`、`instructions`、`timeZone`、`startsAtTime`、`endsAtTime`、`blueprint`、`filters` 和 `answerRevealPolicy`。时间格式为 `HH:mm`，截止不晚于开放时表示次日截止。
- `POST /api/admin/rolling/preview` 接收 `{ config }`，不保存，返回同源互斥后的题量。
- `POST /api/admin/rolling/generate` 使用已保存规则立即生成／重试今天，成功后重复请求不会再建场。
- 题库 AI 任务接口为 `POST /api/admin/question-bank/generate`、`GET /api/admin/question-bank/generation`、`POST /api/admin/question-bank/generation/:id/retry`、`GET /api/admin/question-bank/generation/sources`。创建时缺省为资料生成；定向补题传 `mode: 'supplement'`、`sourceIds`、`difficulty`、`extraPrompt`、`quantity: {mode:'auto', total}` 或 `{mode:'by_type', counts:{single_choice,multiple_choice,true_false,fill_blank}}`。两个模式共用串行执行器与任务进度。
- 模型设置的「测试连接」使用 `POST /api/admin/models/test`，输入沿用设置字段，按当前表单发固定短对话，不写数据库。省略 Key 时只允许沿用同地址已保存的 Key；新地址需显式输入 Key 或选择不用 Key。测试 60 秒超时，成功返回模型 ID 与耗时，失败沿用上游错误码和原因。

同源身份仍使用来源文件集合与规范化后的 `sourceGroup`。系统给一个完整来源的所有题目附加同一个标记，不让模型逐题重写。来源引用对应已有分组时沿用旧标记；新来源按原文位置命名，不随模型标题变化。不同来源可以共用一个知识点分类。同一来源若已有多个冲突分组会提示先统一，跨任务中不同的来源拆分仍需人工检查，数据库不做语义去重。

启动新版本前备份现有数据；迁移 010 增加任务梳理快照及执行标识，迁移 011 增加长期来源目录并从已有任务回填，不改变已有题库题与试卷。首次试用选择「新建 文本文档.txt」，检查完整来源是否全部列出、缺答案的末题是否标明忽略；之后选择知识点或单个来源定向补题，核对题量合计、重复与冲突提示及同源互斥。此次修改前已备份现有 SQLite 数据库。

## 模型格式问题的复现与修复

- 按用户授权用相同资料和已保存的 DeepSeek 配置复现：模型返回 `type: "填空题"`，旧解析只接受 `fill_blank`；混合题型提示词缺少枚举与完整结构示例。
- 已补齐四种题型的英文枚举、完整字段示例和原始定位规则；共享解析接受四个明确中文题型名，不猜测其他题型，答案和引用校验保留。
- 在此前按字符分批的流程中，使用 `deepseek-v4.1-flash` 重新生成，同一份约 1812 字符 TXT 成功入库 6 道单选题，已核对六题标准答案及摘录，结果保留在题库。这只验证了旧流程的题型格式修复。
- 全文来源梳理、批量生成、定向补题和断点继续尚未做真实模型试用；内网模型及更长资料也待对应环境确认。
