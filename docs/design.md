## 1. 目标与交付范围

管理员上传资料，生成并审核一份满分 100 分的试卷，设置考试开放时间并发布。用户输入姓名后查看考试安排，在开放时间内自行点击开始或继续答题。交卷后系统立即判分并展示成绩，并按本场设置公开答案与解析。管理端汇总各场考试的答题情况。

本文件规定首版的完整行为。实现者可以决定组件拆分、布局细节和符合本设计的成熟依赖；不能为了方便实现而改动考试规则、数据含义、权限边界或删减完整流程。发现设计冲突时，先说明冲突和影响，再由用户决定。

### 1.1 用户已经确定的要求

- 项目名为「知卷」，英文标识 `zhijuan`。
- 使用 Nuxt、Vue 3 和 Element Plus，分为管理端和用户端。
- 在可信内网使用；只输入姓名，不增加注册、密码、验证码或第三方登录。
- 管理员名称通过字符串数组配置；匹配名称进入管理端。
- 管理端可设置 Base URL、API Key，刷新获取模型名称并选择模型。
- 从上传文件中生成单选题、多选题、判断题和填空题；可按题型设置题数，自动配分，满分 100 分。
- 用户登录后查看当前考试，点击「开始答题」才建卷计时，逐题翻页作答；登录和刷新首页不自动进入答题页。
- 交卷后提供成绩、错误点、正确答案及原因解析。
- 管理端按考试场次汇总结果。
- 每场考试设置开放起止时间，不同考试的开放区间不能交叉。
- **每场考试可设置答案与解析的公开时间：`immediate` 或 `after_exam`，默认 `immediate`。**
- **使用场景定位为内部培训与知识自测**：成绩供本人与管理员参考，不作为考核、认证、合规举证或奖惩依据。这一句决定了姓名可冒用、固定同卷、默认交卷即公开三条规则在首版是可接受的。
- **题型为单选、多选、判断、填空四类，全部客观题**，交卷即完成判分并出分，不存在异步阅卷与待批阅状态。
- **场次时间默认是当天 00:00 至次日 00:00**（不填写即一整天）；管理员可以填写任意起止时间，届时必须规避与其它已发布场次的时间重叠；**同一天允许多场考试**。
- 新建场次默认时区为 `Asia/Shanghai`，默认名称为该时区当天日期加「测试」，例如 `2026年10月26日 测试`；管理员可以自定义名称和时区。
- **开放窗口内随到随考**，考生在窗口内任意时间进入作答，不集中开考，不设个人限时。
- **题量按题型分别填写**（单选、多选、判断、填空各一个数值），总题数由系统汇总，不单独手填。
- **试卷从候选题池随机抽取一次组成**，抽取完成后即为该场固定试卷：所有考生题目相同、顺序相同，发布后不再重新抽取。
- **场次汇总支持导出 Excel**，每场一个导出按钮，导出该场考生作答记录与成绩。
- **管理员需要参加考试时另用一个不在名单内的姓名**，管理端不提供以管理身份直接作答的入口。

### 1.2 本版采用的实现规则

以下是为避免实现者临时猜测而选定的首版规则，未被用户指定的参数集中在这里。

- 单个 Nuxt 全栈项目、一个 Node 服务进程、SQLite 数据库、本地文件存储。
- 选择题固定四个选项：单选只有一正确项，多选至少两正确项；判断题为「正确／错误」两个固定选项；不包含附件作答和富文本作答。
- 填空题支持多个空和每个空的多个可接受答案；不接受附件作答或富文本作答。
- 每场 1～100 题，按总题数等分 100 分，分值保留两位小数；不设置题型权重或手工配分。
- 资料格式为文字版 PDF、DOCX、UTF-8 TXT、UTF-8 Markdown；不包含扫描件 OCR。
- 组卷时从 AI 生成的候选题目中随机抽取，抽一次即固定；发出后同一场考试使用同一份试卷，不再随机抽题、不打乱题目顺序。
- 同一姓名每场仅有一次答题记录，刷新或再次登录继续原记录；首版不提供重考。
- 计时为正计时：显示本场已用的时、分、秒，不显示倒计时或剩余时间；没有独立的个人限时；开放截止时自动交卷。
- 交卷事务内立即完成全部判分并写入总分；不存在异步阅卷、阅卷队列或「待批阅」状态。
- 判断题与单选题分值相同；多选漏选、错选均不得分；填空题按每个空位的可接受答案匹配，多空按空位计分。
- 管理员可以对任意题目复核改分，改分需填写原因并保留前后记录。
- 默认及格线为 60 分，仅用于统计和结果展示，不影响交卷或答案公开。
- 填空题按短答案设计：每个空的作答输入上限为 20 个字符（正常约 10 个汉字），不做长文本填空。
- 题量按题型分别填写并汇总总题数；抽题后各题型数量必须与设定一致。

### 1.3 不属于首版的功能

不做账号组织管理、考生名单导入、身份防冒用、摄像头监考、切屏惩罚、复杂防作弊、排行榜、独立题库、跨场组卷、向量数据库、在线搜索、OCR、移动 App、分布式队列或多实例部署。不得为这些功能提前增加服务、配置页或占位按钮。

## 2. 架构与模块职责

```text
浏览器：Nuxt 页面 + Element Plus
    │ 同源 /api；Cookie 会话
    ▼
Nuxt 服务端接口
    ├─ 身份与权限：会话、管理员名单、答卷归属
    ├─ 考试服务：草稿、配分、发布、时间冲突、公开规则
    ├─ 答题服务：开始、保存、交卷、截止处理
    ├─ 判分服务：客观判分、总分、人工改分
    ├─ 出题服务：读取资料、生成、校验、随机抽题组卷
    └─ 后台任务：SQLite 持久队列（出题）、截止检查
          │                  │
          ▼                  ▼
    SQLite + 本地资料     已配置的模型服务
```

### 2.1 技术与目录

- 使用 Nuxt 4 的项目结构与 TypeScript；具体兼容版本由实现者选择并写入锁文件，不使用浮动依赖。
- Element Plus 使用其 Nuxt 集成方式，不在项目中另外搭建 Vite SPA 或 React 应用。[官方集成说明](https://element-plus.org/en-US/guide/quickstart.html#nuxt)
- 使用 SQLite 的成熟 Node 驱动和参数化 SQL；使用有序 SQL 迁移文件，不额外引入 ORM。
- 不再单独建立 Express 后端、鉴权平台或通用工作流引擎。
- Excel 导出使用纯 JavaScript 的实现（例如 `exceljs`），不在服务端引入需要本地编译的表格依赖。
- 客户端的状态以页面和组合函数为主；不要仅为少量表单引入全局状态框架。

建议目录如下。可在职责不变的前提下合并小文件，不要求机械地创建每一个文件。

```text
app/
  pages/                 入口、答题、结果、我的记录、管理页面
  layouts/               user、admin 布局
  components/            题目输入、题号导航、编辑器等实际复用组件
  composables/           会话、答题保存与结果读取
  assets/styles/         全局样式与设计变量
server/
  api/                   接口输入校验、权限检查、调用业务服务
  services/              exam、attempt、generation、scoring 等业务
  ai/                    模型服务请求与出题提示词
  db/                    数据库连接、查询、迁移
  plugins/               后台任务与截止检查生命周期
shared/
  types/                 明确区分考生 DTO 与管理员 DTO
data/                    数据库与上传资料；不进入 Git，不公开静态访问
docs/
  design.md              本开发契约
  DEEPSEEK_HANDOFF.md     开发交接说明
```

数据库访问和模型请求只能在服务端执行。API Key 不回传；资料原文仅通过管理员接口提供；标准答案和解析只通过有权限且满足公开条件的接口返回。客户端不得直接导入服务端模型或数据库实体来拼装答题页面。

### 2.2 配置与持久化边界

- 管理员数组配置在 `nuxt.config.ts` 的私有 `runtimeConfig.adminNames`，例如 `['管理员']`；不放在 `runtimeConfig.public` 或 `app.config.ts`。
- 文档说明如何更换名称，以及在所采用部署方式下是否需要重新构建/重启；不能声称修改源码会自动改变已构建的服务。
- 模型服务的 Base URL、API Key、所选模型存入服务端数据库，由管理页面维护，刷新和重启后保留。
- 管理页面只在用户录入新 Key 时将其单向提交给服务端；读取配置只返回 `hasApiKey`，不回传原值或可还原内容，不存入浏览器本地存储。
- 首版数据库中的 Key 依靠服务器文件权限保护，不宣称已经加密。数据库和备份均按敏感数据处理。
- 数据目录独立于构建输出；更新代码或重新构建不能清空数据库和资料。

## 3. 身份与权限边界

### 3.1 姓名规则

- 姓名必填，去除首尾空白并进行 Unicode NFC 规范化，长度为 1～64 个 Unicode 字符。
- 保留大小写与中间空格，不做拼音转换或模糊匹配。管理员匹配使用同一规范化函数，按完整字符串比较。
- 同一规范化姓名代表同一人。真正重名时由用户输入「部门＋姓名」区分，不提供系统猜测或自动合并。
- 管理员身份同样只依赖名称。知道名称即可冒用管理员；知道其他考生姓名即可以其身份续答或查看结果。这是姓名入口的使用边界，不以复杂登录功能替代用户的既定选择。

### 3.2 会话与接口权限

- 登录成功后，服务端创建随机不可预测的会话标识，放入 HttpOnly、SameSite=Strict Cookie；HTTPS 下启用 Secure，内网 HTTP 部署不错误地强制 Secure 导致无法登录。
- 会话在 SQLite 中保存，默认有效期 7 天；过期后重新输入姓名，答卷不丢失。
- 会话只确定规范化姓名；是否为管理员由服务端根据当前管理员数组判断，客户端不能提交 `role`、管理员标志或其他人的姓名来覆盖会话。
- 所有 `/api/admin/**` 均做服务端管理员检查。页面路由守卫只负责导航体验，不代替接口检查。
- 考生接口只读写本会话姓名拥有的答卷。答卷 ID 不是访问凭证，不能换个 ID 就读取别人数据。
- 修改状态的请求限同源，检查 Origin；不开放任意来源 CORS。API Key、会话标识不得写入日志。
- 涉及会话、答卷、成绩及管理内容的响应使用 `Cache-Control: no-store`，不使用共享页面缓存或跨用户缓存。

## 4. 考试状态、时间和发布

### 4.1 状态定义

数据库只存 `draft`、`published` 两种发布状态。页面根据服务端时间计算阶段，避免保存的「进行中」状态过期。

| 页面阶段 | 判定 | 用户行为 |
| --- | --- | --- |
| 草稿 | `status = draft` | 考生不可见 |
| 未开始 | 已发布，`now < startsAt` | 显示开始时间，不创建答卷 |
| 开放中 | 已发布，`startsAt <= now < endsAt` | 开始、续答或查看已交卷结果 |
| 已结束 | 已发布，`now >= endsAt` | 不再作答，可以查看本人结果 |

- 起止时间使用带时区偏移的 ISO 8601 输入，服务端转换为 UTC 毫秒存储和比较。
- 创建考试默认使用 `Asia/Shanghai`，管理员可另选 IANA 时区；起止时间在管理端和用户端均按保存的考试时区展示，并标注时区，不依赖服务器本地时区解析无偏移字符串。
- 服务端时间是唯一判定依据。客户端时钟只用于显示，调整系统时间不能延长考试。
- 常见配置是整天窗口（00:00 至次日 00:00）：此时「开放时长」只界定可进入与可交卷的时段，不构成个人限时；计时器仍只显示已用时间。整天窗口占满一整天，按第 4.2 节的不重叠规则会与同日其它场次冲突；要在同一天安排多场，就为各场填入互不重叠的时段（例如上午场 09:00–11:00、下午场 14:00–16:00），系统不绕过不重叠规则。
- 长窗口配合 `immediate` 公开与同一份试卷，会让先交卷者把题目和答案传给后进入者。首版接受这一风险（场景为培训自测）；需要收紧时由管理员把该场设为 `after_exam`，不需要新增功能。

### 4.2 不重叠规则

开放区间采用 **`[startsAt, endsAt)`**：包含开始时刻，不包含截止时刻。

两场已发布考试满足下面条件就发生冲突：

```text
new.startsAt < existing.endsAt
且 new.endsAt > existing.startsAt
```

相邻考试允许上一场 10:00 截止、下一场 10:00 开始。草稿可以暂存冲突时间，但不能发布。服务端发布时必须在同一个写事务内检查冲突并保存状态，避免两个并发发布同时通过。

### 4.3 发布与锁定

发布前必须同时满足：

1. 标题、起止时间有效，`startsAt < endsAt`，截止时间在未来。
2. 题数为 1～100，题型数量与设定一致，试卷题目校验通过。
3. 每道题都有标准答案、固定解析和有效资料引用。
4. 所有题目分值合计为 10000 个计分单位。
5. 正在生成题目时不可发布。
6. 与其他已发布考试不存在开放时间冲突。

发布后锁定题目、顺序、配分、起止时间、评分标准和答案公开策略。开始前且尚无答卷时可以撤回为草稿再修改；开始后不支持撤回、删除、改题、改时间或更换公开策略，只允许按规则复核改分。新增提前结束或延期功能需另行变更本契约。

## 5. 题型、配分与判分

### 5.1 满分必须精确为 100 分

内部使用整数 `scoreUnits`，**1 单位 = 0.01 分，满分 = 10000 单位**。数据库、配分和求和均使用整数，显示时才除以 100。

设题目总数为 `N`：

```text
base = floor(10000 / N)
remainder = 10000 % N
按固定题目顺序，前 remainder 题各为 base + 1，其余为 base。
```

例如 3 题分别为 33.34、33.33、33.33 分，总和 100 分。每道题显示自己的实际分值，不在交卷时临时加减尾差。服务端按实际题目数量重新配分，不能接收客户端自报分值覆盖配分结果。更改草稿中的目标题数不自动删除既有题目；管理员重新生成或编辑至数量匹配后才可发布。

### 5.2 单选题

- 类型为 `single_choice`，固定四个非空选项，稳定 ID 为 A、B、C、D，只能选择一个。
- 正确选项必须且只能指向其中一个选项 ID。
- 选中正确选项得满分，其他或未答得 0 分。

### 5.3 多选题

- 类型为 `multiple_choice`，固定四个非空选项，稳定 ID 为 A、B、C、D，可以选多个。
- 正确选项集合至少两项，且不能是全部四项。
- 只有提交的选项集合与正确集合**完全一致**时得满分；少选、多选、错选一律 0 分，不设部分分。
- 未答按 0 分处理。

### 5.4 判断题

- 类型为 `true_false`，题干是一句陈述，作答只有两个固定选项：`true`（正确）与 `false`（错误）。
- 标准答案必须是其中之一；匹配得满分，其他或未答得 0 分。

### 5.5 填空题

- 类型为 `fill_blank`，题干通过稳定空位 ID 对应一个或多个输入框，每个空有非空的 `acceptedAnswers` 列表。
- 每个空的作答输入上限为 20 个字符（正常约 10 个汉字），由输入框限制长度，不做长文本填空。
- 答案比较统一做 NFC、去首尾空白、将连续空白合并为一个空格；默认区分大小写，不擅自删除标点、单位或进行语义猜测。
- 可接受的同义词和其他写法在出题及管理员审核阶段列入答案列表，不在判分时临时调用 AI 改变规则。
- 题目分值按第 5.1 节的整数分配方法均分到各空，按空给分，支持部分分；未答的空为 0 分。
- 发布前检查题干空位与答案定义一一对应，不能有重复或不存在的空位。

### 5.6 判分与人工改分

- 全部题型在交卷事务内由服务端判分：单选、多选、判断按命中给满分或 0 分，填空按空给分，总分等于各题得分之和。
- 不在作答过程中逐题提示对错；翻到下一题不代表提交该题获得结果。
- 交卷后立即得到总分，没有排队、没有异步评分、没有「待批阅」状态。
- 未作答与答错都是 0 分，但数据上可区分：未作答题目保存为空答案，结果页显示「未作答」，不显示成答错。
- 管理员可以对已交卷答卷逐题改分，输入新分值和必填原因；分值必须在 0 与该题满分之间，精度最多两位小数，服务端转换为整数单位。
- 保留自动判分、人工覆盖分值、改分前后分数、操作管理员姓名、原因和时间；最终分值优先使用人工覆盖值，考生结果标注「人工复核」。
- 每次改分后重新计算答卷总分；汇总统计读取最新最终分值。
- 改分接口不能修改标准答案、试卷满分或其他考生的身份信息。

## 6. 用户端流程与保存规则

### 6.1 登录后的去向

```text
输入姓名
  ├─ 管理员 → 管理端概览
  └─ 普通用户
       ├─ 有开放考试且没有答卷 → 展示考试信息，点击「开始答题」后创建答卷并计时
       ├─ 当前场次答卷未提交 → 展示「继续答题」入口，进入后沿用开始时间
       ├─ 当前场次已交卷 → 展示「查看成绩」入口
       └─ 没有开放考试 → 显示下一场时间及本人答题记录入口
```

登录后主动获取考试安排，加载中不显示「暂无考试」；仅登录或刷新首页不创建答卷，也不自动进入考试。考试标题、说明在首页和第一题上方可读；没有考试时给出具体状态，不显示空白表单。即使考试已经结束，重新输入原姓名也能通过本人记录查看之前的结果，保证延迟公开模式有可用入口。

### 6.2 逐题界面

```text
考试标题                          已用 08:32
━━━━━━━━━━━━ 进度 ━━━━━━━━━━━━        5 / 20

单选题 · 5.00 分
题干……

[ A  选项内容                         ]
[ B  选项内容                         ]
[ C  选项内容                         ]
[ D  选项内容                         ]

已保存 14:08:32        [题号] [上一题] [下一题]
```

- 单题主视图，不把整份试卷铺成长表单；题号面板可跳转，并区分当前、已答、未答。
- 填空题题面将内部空位标识显示为 `_____`，各输入框标注空位序号及分值；多选题提示「可多选」；判断题使用「正确／错误」两个选项按钮，图标分别为绿色勾和红色叉，不显示内部选项 ID。
- 选项单击只改变答案，不自动跳题；允许回到之前的题修改。
- 最后一题提供「交卷」。交卷确认显示已答题数、未答题数，允许带空题交卷，不强制全部填满。
- 不加入生命值、连胜奖励、随机音效或逐题正确提示，避免把考试变成另一个产品。

### 6.3 保存、并发与计时

- 开始时间由服务端创建答卷时写入；刷新、退出或再次登录不重置。
- 输入变化后约 600ms 自动保存。页面明确显示保存中、已保存、保存失败，并给出重试入口。
- 同一页面串行发送保存请求；输入在请求期间继续变化时，保存最新内容，不能让旧请求覆盖新内容。
- 答卷具有递增 `version`。每次保存携带 `expectedVersion`，不匹配时返回 409，不覆盖其他标签页的更新；页面保留本地未保存内容，提示重新载入服务器记录后再决定是否重新输入。
- 切题前等待该题的待保存请求完成；失败时保留输入，不显示已保存。
- 手动交卷携带当前完整答案快照与 `expectedVersion`，服务端在同一个事务中校验、保存并冻结。确认成功之前不清空本地输入。
- 页面只显示本场已用时间，根据服务端返回的 `serverNow` 与 `startedAt` 计算，不显示倒计时或剩余时间；页面重新激活时重新同步，而非单靠本地秒数累加。
- 不承诺未成功发送到服务器的内容能在关闭浏览器或断网后恢复。离线或保存失败时明确提示尚未保存。

### 6.4 手动与截止交卷

- 答卷状态只有 `in_progress` 和 `submitted`；提交后禁止继续保存。
- 手动交卷请求到达服务端时仍须满足 `now < endsAt`。不能根据客户端时间或按钮点击时间接收迟到答案。
- 服务端后台每秒检查已到截止时间的进行中答卷，按最后成功保存的答案交卷。用户关闭浏览器也会执行。
- 启动时补处理停机期间已经截止的答卷；访问过期答卷时也先按同一规则处理，避免依赖定时器恰好执行。
- 截止时刻为 `submittedAt = endsAt`，手动交卷为服务端实际提交时刻；`submitReason` 分别为 `deadline`、`manual`。停机补处理不将额外停机时间计入答题用时。
- 截止后收到包含新答案的提交请求，不采纳新内容；按已保存内容完成截止交卷并返回明确的截止状态。
- 重复交卷返回已存在的提交结果，不改写答案，不重复计分。

## 7. 交卷判分与答案公开

### 7.1 交卷即完成判分

- 交卷请求到达后，在同一个短事务内完成：校验 `expectedVersion`、写入完整答案快照、按第 5.6 节判分、写入总分、把答卷标记为 `submitted`。
- 事务提交后该答卷的分数即为最终分值，页面直接展示。不存在排队、异步评分、评分失败等中间状态，也不存在需要重试的评分任务。
- 交卷失败时事务整体回滚，答卷仍是进行中，本地答案不清空。
- `attempts` 只保留 `status`（`in_progress` / `submitted`）与 `total_score_units`；不再有 `grading_status` 字段。

### 7.2 按场次配置公开时间

管理端字段名称为「答案与解析公开时间」，单选：

- **交卷后立即公开**：`answerRevealPolicy = immediate`，新建考试默认值。
- **本场考试结束后公开**：`answerRevealPolicy = after_exam`。

公开条件由服务端统一计算：

```text
canReveal = 已交卷 && (
  answerRevealPolicy == 'immediate'
  || serverNow >= exam.endsAt
)
```

- 成绩在交卷后立即展示，不因延迟公开而推迟。
- `immediate` 模式下，交卷即可查看逐题得分、标准答案、本人作答与固定解析。
- `after_exam` 模式下，结束前仅展示总成绩、用时和本人原答案；不返回标准答案、逐题分数、对错标志或其他可泄露作答结论的内容。
- 延迟页面明确显示「答案与解析将在 ×月×日 ×时×分（考试时区）公开」，到时重新请求结果，不只是在前端隐藏已有内容。
- 作答接口、结果接口、SSR 页面载荷与任何共享缓存都执行同一公开边界。禁止把完整试卷对象下发后用 CSS、折叠面板或前端条件遮住答案。
- 管理端可查看完整试卷和已提交答卷，不受考生公开策略限制；概览可统计进行中人数，但不提供偷看考生未交卷输入的页面。

## 8. 文件处理、AI 出题和后台任务

### 8.1 上传与资料内容

- 每场最多 5 份文件，单份最多 20MB，合并后的正文最多 40000 个 Unicode 字符；这些是首版明确上限，不假定任意模型都能接受任意长度。
- 由服务端校验文件大小、扩展名和实际可解析格式。DOCX 解析也限制解压后的资源规模，不能只检查压缩包大小。
- 文件使用服务端生成的存储 ID，不用上传文件名拼接路径；保存于私有数据目录，不放入 `public/`。
- 文字版 PDF 按页保留来源定位，DOCX 按段落保留定位，TXT/Markdown 按行段定位。管理员先看到提取正文预览，再生成题目。
- 无正文、加密 PDF、扫描件或损坏文件给出具体原因；超限要求拆分或精简，不静默截断、不生成空白试卷。
- 不渲染上传文件中的 HTML，不执行文档宏、脚本、链接或模型给出的命令。
- 草稿删除资料时检查引用；已有题目引用的资料须先移除相关题目，已发布资料不允许删除。

### 8.2 模型连接约定

首版只实现 **OpenAI 兼容的文本接口**，不同时适配各厂商原生协议。

- Base URL 是完整 API 前缀，例如 `https://model.example/v1`；请求模型列表时追加 `/models`，出题生成时追加 `/chat/completions`。
- 保留原有路径前缀，只规范化末尾斜杠；不能自动再拼一次 `/v1`，也不能用错误的 URL 拼接方式丢失已有路径。
- 只接受 HTTP/HTTPS URL，允许可信内网服务地址，不把它改造成通用匿名代理；只有管理员接口能更改地址。
- 模型列表使用 `GET /models`，读取 `data[].id`；文本调用使用 `POST /chat/completions`，最小请求包含 `model`、`messages`、`stream: false`，从 `choices[0].message.content` 读取文本。[OpenAI Docs：模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)、[文本调用](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- 鉴权使用服务端保存的 Bearer Key，不向前端暴露请求头。读取设置返回 `hasApiKey`；更新时省略 `apiKey` 表示保持原值，非空字符串表示替换，显式 `null` 表示清除；禁止把遮罩字符当成新 Key 保存。
- 管理员先保存设置，再点击「刷新模型」，从返回列表选择并保存模型。失败时保留已有设置和选择，显示错误，不拿硬编码模型充当成功结果。
- 不强制兼容端支持 Structured Outputs、工具调用或模型专有参数；通过提示词要求 JSON，再由服务端严格校验。
- 单次模型请求超时为 120 秒；超时、鉴权失败、限流、无内容和无效 JSON 分别给出可理解的错误。首版不自动重试、不换模型、不切换供应商。
- 任务开始时读取当前模型设置，记录实际 Base URL 和模型 ID；任务中途不更换连接。人工重试使用当前设置并记录实际模型，页面可查，不宣称重试仍使用旧模型。

### 8.3 出题流程与输出校验

1. 保存草稿设置：各题型数量、难度（简单/适中/困难，默认适中）、出题补充说明、资料列表。
2. 创建出题任务，记录草稿版本并锁定该草稿的题目和资料编辑，避免异步结果覆盖新的人工修改。
3. 将可定位的资料正文、目标数量和明确格式要求发送给模型。资料中的指令只作为资料内容，不改变系统要求。
4. 模型返回题干、选项、标准答案、固定解析和资料引用；数据库 ID、选项／空位 ID 与分值由服务端规范化生成。模型使用的临时空位编号由服务端映射为稳定 ID，并同步替换题干与答案结构的引用，不能只改一处。
5. 服务端校验题数、题型、选项、答案对应关系、来源 ID 和定位，并检查引用摘录在归一化后（NFC、合并连续空白、去软换行与页码行）能命中同一页或同一段。无效结果不能作为成功试卷落库。
6. 全部校验成功后，在一个事务中写入草稿题目并计算分值；原有题目在失败时保留。
7. 随机抽题：出题任务按各题型设定数量的 1.5 倍（向上取整，单题型最多 60 题）请求候选，校验通过后按题型分别随机抽取设定数量，组成该场固定试卷；未抽中的候选不落库、不保留。
8. 管理员预览并编辑题目、答案和解析，确认后发布。引用真实存在只说明来源可核对，题目含义和答案正确性仍由管理员审核。

本版不做自动联网补资料或自动多轮修复 JSON。可以去除唯一包裹整段内容的 Markdown 代码围栏，然后解析 JSON；禁止 `eval`、猜测截取一段貌似 JSON 的内容或填补缺失字段冒充生成成功。

### 8.4 持久任务与失败恢复

- 出题使用 SQLite 中的 `jobs` 表，状态为 `queued`、`running`、`succeeded`、`failed`，不是仅存在页面或进程内存的 Promise。首版只有出题这一种任务类型。
- 单服务进程内同时执行一个 AI 任务；领取任务与状态修改通过数据库事务完成。同一草稿只能有一个活动出题任务。
- 单批模型请求超时 120 秒；长卷按题型分批请求（每批不超过 20 题），每批独立校验，任一关键批次失败则整次生成按失败处理，全部批次成功后才在一个事务内写入草稿题目，任务错误信息记录失败批次与原因。
- 任务记录进度（已完成批次数／总批次数），页面按 1 秒轮询任务接口显示进度；进度可见不代表半成品入库。
- 服务重启后继续处理尚未领取的 `queued` 任务；将中断的 `running` 任务标记为失败，说明处理中断，交由管理员重试，不自动重新发起可能重复计费的请求。
- 客户端通过任务接口轮询状态；离开页面不会取消已经保存的出题任务。
- AI 调用期间不持有数据库长事务；截止检查独立运行，不被一个等待中的 AI 请求阻塞。
- 重试只允许失败且仍需处理的任务，原子地改回排队状态；重复点击、已完成任务或正在执行的任务不能重复入队。
- 出题失败后解锁草稿。旧出题任务重试前核对草稿版本与资料引用；输入已变更则拒绝重试旧任务，要求按当前草稿重新生成，不能覆盖用户后续编辑。
- 日志保留任务 ID、类型、时间和脱敏错误，不输出 Key、鉴权头或完整上传资料。

## 9. 管理端页面与统计口径

### 9.1 页面与操作

| 页面 | 内容与主操作 |
| --- | --- |
| 概览 `/admin` | 当前考试、下一场、已开始/进行中/已交卷人数，进入场次结果 |
| 考试列表 `/admin/exams` | 新建草稿、查看状态与时间、进入编辑或结果 |
| 考试编辑 `/admin/exams/:id` | 基本信息、文件预览、题数/难度、出题、题目编辑、公开策略、发布/撤回 |
| 场次汇总 `/admin/exams/:id/results` | 汇总指标、考生列表、逐题表现、筛选、进入个人答卷、导出本场 Excel |
| 答卷详情 `/admin/attempts/:id` | 已交卷答案、自动判分、解析、人工改分记录 |
| 模型设置 `/admin/settings` | Base URL、新 Key 输入、已配置状态、模型刷新和选择 |

生成中、保存中、发布失败、时间冲突和字段校验失败都要有真实状态与对应操作。生成按钮不能只弹出成功消息却没有真实题目；配置未就绪时明确指出缺少哪项并链接到设置。

### 9.2 汇总口径

- 参与人数：该考试的答卷总数；由于没有预设名单，不能显示无法计算的「应考人数」或「缺考人数」。
- 进行中：`status = in_progress`；已交卷：`status = submitted`。
- 平均分、最高分、最低分、及格率：统计全部已交卷答卷，及格为总分至少 6000 单位；展示「基于 X 份已交卷答卷」。没有数据时显示「—」，不是 0 分或 NaN。
- 单题正确率、部分得分率、零分率：统计该场全部已交卷答卷；比例旁显示样本数。未作答在交卷后按 0 分计入。
- 用时：`submittedAt - startedAt`，进行中显示当前已用时间。
- 所有查询都按 `examId` 过滤；考生列表每页 20 人，按开始时间倒序，排序增加 ID 作为稳定次序。人工改分后汇总读取最新最终分值。

## 10. 数据结构

表名使用英文下划线，接口字段使用英文驼峰。ID 由服务端生成，分值为整数，时间为 UTC 毫秒。下表是最低数据契约，不要求把每个显示字段冗余存库。

| 表 | 关键字段与约束 |
| --- | --- |
| `provider_settings` | 单条记录；`base_url`、`api_key`、`model_id`、`updated_at`，只供服务端读取 |
| `exams` | `id`、`title`、`instructions`、`status`、`starts_at`、`ends_at`、`time_zone`、`answer_reveal_policy`（默认 immediate）、`blueprint_json`、`version`、创建/更新时间 |
| `documents` | `id`、`exam_id`、原文件名、格式、字节数、私有相对存储路径、提取正文片段及定位、解析状态/错误、创建时间 |
| `questions` | `id`、`exam_id`、`position`、`type`、`stem`、`options_json`、`answer_definition_json`、`explanation`、`source_refs_json`、`max_score_units`；同场 position 唯一 |
| `attempts` | `id`、`exam_id`、`name`、`name_key`、`status`、`started_at`、`submitted_at`、`submit_reason`、`total_score_units`（未交卷时为 NULL）、`version`；`UNIQUE(exam_id, name_key)` |
| `answers` | `attempt_id`、`question_id`、`answer_json`、`auto_score_units`（交卷前可空）、`override_score_units`（可空）、更新时间；同答卷同题唯一 |
| `jobs` | `id`、`type`（首版只有 generation）、`exam_id`、状态、输入版本与必要输入、进度、实际模型与 Base URL、脱敏错误、创建/开始/结束时间；不存 Key |
| `sessions` | 随机会话标识、规范化姓名、创建/过期时间；角色由当前配置计算，不相信客户端角色 |
| `grade_changes` | `id`、`attempt_id`、`question_id`、旧/新最终分数、原因、管理员姓名、时间 |

题目类型对应的内部结构：

```ts
type QuestionType = 'single_choice' | 'multiple_choice' | 'true_false' | 'fill_blank'
type AnswerRevealPolicy = 'immediate' | 'after_exam'

// single_choice:   options [{ id: 'A', text: '...' }, ...]
//                  answerDefinition { correctOptionIds: ['B'] }
// multiple_choice: answerDefinition { correctOptionIds: ['A', 'C'] }（至少两项、不能全选）
// true_false:      options 固定为 [{ id: 'true', text: '正确' }, { id: 'false', text: '错误' }]
//                  answerDefinition { correctOptionIds: ['true'] }
// fill_blank:      answerDefinition { blanks: [{ id, acceptedAnswers: ['...'] }] }

// 考生答案，不包含任何正确性或评分字段：
type CandidateAnswer =
  | { type: 'single_choice'; selectedOptionIds: string[] }
  | { type: 'multiple_choice'; selectedOptionIds: string[] }
  | { type: 'true_false'; selectedOptionIds: string[] }
  | { type: 'fill_blank'; values: Record<string, string> }
```

- 候选答案的类型、选项 ID、空位 ID 必须与该答卷所属试卷中的题目一致。
- `questions` 的数据库实体是内部对象，不能直接作为考生 DTO 序列化。作答 DTO 明确选取题干、选项/空位、题型、顺序和满分；不包含答案定义、标准答案、资料原文或解析。
- 考生结果 DTO 在服务端根据 `canReveal` 显式构造。关闭公开时敏感字段从结构中省略，而非改成前端仍可读取的隐藏数据。
- `result` 的最小公共字段为 `attemptId`、`totalScoreUnits`、`startedAt`、`submittedAt`、`serverNow`、`canReveal`、`revealAt` 和本人 `answers`。仅当 `canReveal = true` 时增加逐题得分、标准答案与解析；`revealAt` 为交卷时刻或本场截止时刻。
- 开启外键、必要唯一约束与索引。发布冲突检查、开始答卷的去重、保存、交卷、评分写入和改分使用各自所需的短事务。
- 数据库迁移有版本记录，随服务端构建可用；不能靠开发目录中偶然存在的 SQL 文件运行生产服务。不得通过删库重建处理正常升级。

## 11. 服务端接口契约

以下路径统一带 `/api`。JSON 成功响应为 `{ data: ... }`；错误为 `{ error: { code, message, details? } }`，错误信息不包含密钥或原始上游敏感响应。

### 11.1 登录与考生接口

| 方法与路径 | 输入/行为 | 权限与返回重点 |
| --- | --- | --- |
| `POST /auth/login` | `{ name }` | 创建 Cookie 会话；返回服务端判定的角色和导航所需信息 |
| `GET /auth/session` | 无 | 返回当前姓名/角色或未登录状态，不含会话标识 |
| `POST /auth/logout` | 无 | 删除当前会话及 Cookie，不删除答卷 |
| `GET /exams/current` | 无 | 已登录；当前场次基本信息，或下一场时间，不返回题目答案 |
| `GET /me/attempts` | `page`，每页 20 | 只列本人记录和结果入口，不能指定他人姓名 |
| `POST /attempts/start` | 无 | 服务端选取当前开放考试；创建或返回本人的唯一答卷；无当前考试不创建 |
| `GET /attempts/:id` | 无 | 本人答卷；返回作答 DTO、本人保存答案、version、serverNow、startedAt、endsAt、状态 |
| `PATCH /attempts/:id/answers/:questionId` | `{ expectedVersion, answer }` | 仅开放期本人进行中答卷；返回新 version 和 savedAt |
| `POST /attempts/:id/submit` | `{ expectedVersion, answers }`，完整答案快照 | 同一事务内保存、判分、交卷，直接返回最终总分；重复提交返回已有结果，不改写答案 |
| `GET /attempts/:id/result` | 无 | 本人且已交卷；返回总分、用时、公开时间、canReveal、按公开规则裁剪的逐题内容 |

`GET /attempts/:id` 在交卷后仍只返回安全的作答内容和已提交状态，页面转到结果接口；不得借此绕过延迟公开。结果页不需要轮询评分状态，但要在 `revealAt` 时刻重新请求一次以拿到公开后的逐题内容；页面重新激活时也同步公开状态。

### 11.2 管理员接口

以下接口全部需要服务端管理员身份，方法与用途不能用一个不受约束的通用「执行操作」接口替代。

| 方法与路径 | 行为与约束 |
| --- | --- |
| `GET /admin/settings` | 返回 baseUrl、modelId、hasApiKey，不返回 Key |
| `PUT /admin/settings` | 保存设置；Key 的省略/替换/清除遵循第 8.2 节 |
| `POST /admin/models/refresh` | 使用已保存设置请求模型列表，返回模型 ID 列表，不自动换掉已选模型 |
| `GET /admin/exams` | 分页列出场次及服务端计算的阶段 |
| `POST /admin/exams` | 新建草稿，默认公开策略 immediate |
| `GET /admin/exams/:id` | 管理员完整草稿/试卷内容与版本 |
| `PATCH /admin/exams/:id` | expectedVersion + 基本信息/时间/公开策略/出题设定；仅未锁定草稿可改 |
| `DELETE /admin/exams/:id` | 仅无活动任务的草稿可删；不删除已发布考试、答卷或成绩 |
| `POST /admin/exams/:id/documents` | 上传并提取资料，返回元数据、正文预览或明确错误 |
| `DELETE /admin/exams/:id/documents/:documentId` | 仅草稿且无题目引用、无活动出题任务可删除 |
| `POST /admin/exams/:id/generate` | expectedVersion；使用已保存设定创建出题任务，返回 202 和 jobId |
| `PUT /admin/exams/:id/questions` | expectedVersion + 完整题目草稿，校验后整体保存，由服务端重新配分 |
| `POST /admin/exams/:id/publish` | expectedVersion；事务内校验、检查时间冲突并发布 |
| `POST /admin/exams/:id/unpublish` | expectedVersion；仅开始前且无答卷可撤回草稿 |
| `GET /admin/exams/:id/results` | 本场汇总和分页考生列表，支持姓名、及格与否、是否人工复核筛选 |
| `GET /admin/attempts/:id` | 已交卷的完整答卷与判分明细；进行中只返回基本状态 |
| `GET /admin/exams/:id/results/export` | 导出本场 Excel（`.xlsx`）；跟随当前筛选条件，每行一名考生：姓名、开始时间、交卷时间、用时、总分、是否及格、是否人工复核；分值以两位小数呈现；不包含 API Key 或会话标识 |
| `PATCH /admin/attempts/:id/answers/:questionId/grade` | expectedVersion + score（十进制字符串，如 "3.50"）+ reason；服务端转换计分单位，按人工复核规则保存并重算 |
| `GET /admin/jobs/:id` | 任务状态、进度、实际模型及脱敏错误 |
| `POST /admin/jobs/:id/retry` | 仅合法失败任务可以重新排队，不重复创建任务 |

### 11.3 并发与错误语义

- 401：没有有效会话；403：不是管理员或无操作权限；404：资源不存在或不属于本考生，避免枚举他人记录。
- 400：格式错误；422：字段或题目内容不满足规则；409：时间冲突、版本冲突、任务忙、已截止、发布后禁止修改等业务状态冲突。
- 上游失败返回脱敏的模型服务错误与适当状态码；异步任务失败通过任务状态返回，不能在页面轮询时伪装成成功任务。
- `EXAM_TIME_CONFLICT` 返回冲突考试的标题和时间，供管理员调整；`VERSION_CONFLICT` 提示刷新；`EXAM_CLOSED` 说明采用最后已保存答案。
- 发布、保存和提交必须在写入事务内再次检查状态、版本和服务端时间，不能只在接口开始时检查。

## 12. 视觉与交互方向

- 管理端采用清晰的侧栏、表单、表格和状态标签；用户端采用轻量单题界面。两端使用同一组颜色、字体和按钮规则，但不强行共用相同布局。
- 主色为深绿 `#15803D`，背景 `#F7F9F7`，正文 `#17211B`，浅绿用于选中背景，错误使用明确文字与红色提示，不只靠颜色表达。
- 使用本机中文系统字体，不依赖内网访问外部字体 CDN；正文至少 16px，主要按钮触控区域至少 44px。
- 答题区域桌面居中、最大宽度约 800px，移动端单列；底部操作区不遮挡输入内容，长题干可以自然滚动。
- 翻题仅用约 150～200ms 的轻微过渡，尊重减少动态效果设置，不阻塞输入。不生成或引入未确认的品牌插画、吉祥物或装饰资产。
- 输入框有可见标签；键盘可操作；计时器使用等宽数字，避免布局抖动。保存、生成和提交状态使用真实接口结果。

- [ ] 不同考试的答卷和统计不会混合；无答卷时指标显示「—」。
- [ ] 服务重启不会丢失资料和答卷；已排队任务继续，中断任务明确失败，过期答卷得到补处理。
- [ ] 移动端能完整输入和交卷，底部按钮不挡住内容，长题干/长答案不会撑破布局。

### 14.2 实现默认项

### 14.3 已知风险与部署责任

- 内网 HTTPS 与反向代理配置由部署方负责，本文件不规定证书方案。
- 姓名即身份意味着同一姓名可被冒用；因成绩不作考核依据，v0.3 接受该风险，不增加密码或验证码。
- 单服务进程同时只执行一个 AI 出题任务，多场同时生成时排队时间会变长；首版不做并发调度。
