# 知卷增补设计：题库与复用组卷

日期：2026-11-11
状态：代码已实现，数据库升级与页面交互待用户试用确认

用途：题库与复用组卷的现行约定。AI 生成与定向补题详见 [题库 AI 生成与定向补题](question-bank-generation.md)。每日场次详见 [滚动出题与题库生成](rolling-bank-plan.md)。

## 1. 日常从题库组卷，AI 只在需要新题时使用

管理员围绕固定的培训重点，积累可直接复用的单选、多选、判断和填空题。创建考试时，选择知识点和各题型数量，直接从题库抽取；也可以手动挑题。只有缺少合适题目或资料内容变化时，才使用现有 AI 出题功能补充新题。

例如，管理员选择几个知识点，设置单选 6 题、判断 4 题、填空 2 题。题库充足时直接组成 12 题的草稿，不调用模型；判断题只有 3 题时，显示缺少 1 题，由管理员调整范围、题数或主动补题。

核心流程：

```text
题库 AI 生成 / 场次 AI 出题 / 人工编题 / 历史试卷选题
    → 优先匹配已有知识点，保存到题库并直接启用
    → 按知识点、题型、难度选题或随机组卷
    → 按同源考点互斥选题，复制为本场独立试题并发布
```

题库保存可复用的题目，不保存固定分值。考试仍按本场总题数等分 100 分。考后汇总同一道题的作答表现，达到样本量和错误率条件时，在题库标记「易错」，便于管理员检查培训重点、题目表述与答案。

## 2. 范围与现有契约的关系

### 2.1 本次实现范围

- 独立题库管理页：查询、人工录入、编辑、启用、停用、删除。
- 从现有场次选择已保存题目，批量存入题库。
- 每题记录一个主要知识点、题型、难度、资料出处及可选的同源考点分组。
- 题库内 AI 通读全文，归纳知识点及完整来源，再逐来源生成多道题并记录同源关系；不要求输入考点数量，每个来源校验后直接入库，失败可继续未完成来源。
- 题库列表支持多选删除，启用中的题也可直接删除。
- 创建或编辑考试草稿时，支持题库随机组卷和手动追加题目。
- 题库组卷的资料引用转换、试题副本、并发控制和错误反馈。
- 资料库删除保护与题库引用展示。
- 汇总题库题的已交卷作答表现，在题库显示人数、错误率及自动「易错」标记，并支持查看易错题集合。

### 2.2 保持不变的业务规则

- 保留现有上传资料、AI 出题、编辑试题、发布考试的完整入口；原有流程不要求先建立题库或填写知识点。
- 同一场考试只抽题一次，形成固定试卷，所有考生题目和顺序相同。再次组卷只能由管理员在可编辑草稿上主动执行。
- 保留四类客观题、每场 1～100 题、整数 `scoreUnits` 合计 10000、既有判分和人工复核规则。
- 保留姓名身份、每人每场一次、服务端截止和默认 `answerRevealPolicy = immediate`；允许多场同时开放，由考生自选。
- 发布后仍锁定试题和评分标准。题库编辑、停用或删除不会修改任何已有场次。
- 题库查询、人工录题和组卷不要求配置模型，也不创建 AI 任务。

### 2.3 本版不增加的能力

不做考生个人随机卷、选项乱序、刷题模式、重考、个人错题本、错题推荐、通用跨场统计报表、知识图谱、向量检索、语义去重、Excel 导入导出题库、知识点树或复杂题目版本历史。跨场统计限于本文规定的题库易错题标记，不增加个人学习档案或推荐算法。

题库新增专属 AI 任务，直接生成并入库，和场次出题共用单进程串行执行器；原有场次 AI 出题、候选池和选题入库流程不变。滚动出题只使用题库，不会触发模型补题。

### 2.4 契约适用顺序

本文件是 `docs/design.md`、`docs/impl-contract.md` 和 `docs/library-feature.md` 的题库增补设计。旧文档中「不做独立题库、跨场组卷」的范围限制，在本文件明确规定的管理员题库复用范围内解除；其余规则继续适用。

现有 AI 出题方式仍保持一次性候选池，不因新增题库改变其任务输入、批次、重试、输出或失败恢复契约。`docs/DEEPSEEK_HANDOFF.md` 是首版的历史交接材料，不能用其中「尚无应用代码」等描述重新初始化项目。后续实施本功能使用本文第 11 节的交接任务。

## 3. 题库题目与启停规则

### 3.1 内容与分类

每道题包含：

- 题型、题干、选项或空位、标准答案、解析；复用现有 `QuestionType`、`QuestionOption`、`AnswerDefinition` 和 `Difficulty`。
- `knowledgePoint`：一个主要知识点，NFC 规范化并去首尾空白，1～100 个 Unicode 字符。使用可输入新值的选择框，候选来自已有题目的去重值，不建立知识点管理表。一个知识点可以有多种题型。
- `difficulty`：`easy | normal | hard`。人工新增默认 `normal`；从场次入库时默认取该场 `blueprint.difficulty`，管理员可以逐题调整，不假定模型已经给出逐题难度。
- `sourceGroup`：可选同源考点名称，最多 200 字。同一来源文件集合与规范化后的同名标记组成一组；空值表示独立题。题库 AI 先整理完整来源，由系统为该来源的所有题型和多道候选题附加同一标记，管理员可以编辑合并。未归组的旧题仍保持独立，不按整份文件或段落自动合并。
- 至少一条可核对的资料引用，指向资料库文件及其定位段。
- 启停状态、递增版本、创建和更新时间。
- 从场次入库的题目保留来源场次 ID 和来源题目 ID；人工新增的来源为空。

题库不接受没有出处的启用题。人工录题也从资料库选择文件、定位段和摘录。现有题型、字符上限、固定四个选择项、填空答案及引用摘录长度规则保持一致，不增加另一套判分口径。

### 3.2 保存即启用

| 状态 | 页面名称 | 可参与组卷 | 操作规则 |
| --- | --- | --- | --- |
| `active` | 已启用 | 是 | 新建或从场次入库后的默认状态；修改后仍可组卷，也可以停用 |
| `disabled` | 已停用 | 否 | 可以编辑、重新启用或删除；编辑后仍保持停用 |

保存题目时要求题型结构、知识点和引用完整有效，成功后直接启用。表单未保存内容留在当前编辑界面，不另做服务端半成品草稿。

不设置审核步骤。管理员主动停用的题目，保存后仍保持停用；点击「启用」时服务端重新校验内容与引用。数据库保留旧 `draft` 约束和审核列，不再读取或返回审核记录；运行时状态只有启用、停用，启用接口为 `/enable`，审核接口移除。迁移将旧待审核题转为 `active`，不改变已停用题。

修改已有题目的内容、状态或执行删除时必须携带本题的 `expectedVersion`；保存和状态变更成功后 `version += 1`。新增题目从版本 1 开始，从场次入库检查来源场次版本。版本冲突不覆盖当前表单。题库版本只用于并发控制和记录组卷来源，不提供历史版本回滚。

### 3.3 精确重复与删除

对规范化后的题目计算可直接比较的 `contentKey`：

```ts
const normalize = (text: string) => text.normalize('NFC').trim().replace(/\s+/gu, ' ')
const contentKey = JSON.stringify([
  type,
  normalize(stem),
  options.map(option => [option.id, normalize(option.text)]),
])
```

使用已经规范化的选项 ID 和顺序；填空题的 `options` 为空数组。答案、解析、来源和分类不参与此键，避免同一题干和选项因答案不同被存成两道题。题干相同但选项内容不同可以并存。此规则只检查精确重复，不判断改写题是否同义，不调用模型。

`contentKey` 在题库中唯一，涵盖所有状态。重复新增或编辑时返回已有题目 ID 和状态，供管理员查看或修改。从场次批量入库有重复时整批不写入，并指出重复项。题库 AI 逐来源生成时，精确重复不覆盖已有题，明确统计跳过数量；同题但标准答案不同则记录冲突，不写入新题，页面列出新旧答案并可打开已有题。同源同题型但题干或选项不同的题目可并存。具体生成与恢复契约见 [题库 AI 生成与定向补题](question-bank-generation.md)。

启用题和停用题都可直接删除，列表支持当前页多选。批量请求携带各题 ID 与版本，全部核对后一次性删除；冲突时整批回滚。删除只影响题库题及其题库引用记录，不删除场次试题或资料文件；已有考试保留独立副本与同源组快照，来源题目不存在时显示「来源题库题目已删除」。不做回收站。

## 4. 让已有好题进入题库

### 4.1 从场次选题入库

在场次题目列表提供勾选和「存入题库」操作，草稿、已发布和已结束场次都可以作为来源。入库只读取场次，不修改其试题、版本、发布状态或答卷。

操作流程：

1. 有未保存的题目修改时，先保存或明确放弃；服务端只读取已保存题目，不能把页面草稿冒充服务器内容入库。
2. 在弹窗中预览所选题目的答案、解析和出处。知识点优先匹配已有分类：将完整分类清单提供给模型，同场次、同来源资料使用过的分类排在前面；模型选择编号，服务端使用对应的原名称，只有确无适合的分类才新增。支持批量填写知识点和难度后逐题调整。
3. 请求携带 `expectedExamVersion`，逐题校验题目属于该场次、结构和引用有效，并将场次 `documentId` 转为对应的 `libraryFileId`。
4. 本场有活动 AI 任务时不允许入库，避免把正在被替换的旧题误当新结果。题目缺少有效资料库对应记录时明确报错，不伪造引用或自动复制文件。
5. 单次最多入库 100 道，全部通过后在一个短事务中保存为 `active`，直接参与组卷。知识点建议按每批 50 题获取；模型不可用时优先沿用同场次或相同资料已有的知识点，仍可手工调整。

选择题库导入过的场次题再次入库，也按精确重复规则处理；若本场已经改成不同内容，可以作为新题入库，不反向修改原题库题。

### 4.2 人工新增与 AI 补题

题库页可以人工新增完整题目，保存后直接启用。题目编辑能力复用现有实现；仅在场次编辑器和题库编辑器实际共享的字段上提取小组件，不重写现有题目编辑和保存状态。

题库「AI 生成」选择 1–5 份资料、难度及可选补充要求，不输入考点或题目数量。AI 先通读全文，归纳知识点和各分类下的完整来源；系统核对每个原文段已被归入来源或记录忽略原因，再按来源逐题调用模型，每次只出一道并保存后再请求下一道，每个来源默认最多 6 道候选、无合适新题时提前停止。一个来源可以生成多个题型及多道同类题，不强凑数量或四种题型，整份资料的总题数不限制为 6 道。进度展示知识点与来源清单、已处理与失败情况、实际入库数及相同题跳过数。每次请求校验后与进度一起提交；请求最多尝试 3 次，仍失败则记录错误并继续后面的请求及来源。已有成功结果不回滚，关闭窗口不影响执行。原有场次 AI 入口同时保留。

自动分配题型时，提示词列出四种 `type` 英文枚举及结构示例，但每次只允许生成一道题；指定题型时仅发送当前题型的规则和示例。解析端允许将「单选题／多选题／判断题／填空题」这四个明确中文名称归一化为对应枚举，不推测「选择题」等含糊值；原有题型、答案结构和引用校验继续执行。未知题型报错包含来源、题号和模型实际返回值。原文已有习题时只使用题干及答案完整的条目，分行答案随来源快照一同交给模型。同源分组和原文引用由系统附加，不让模型重写文件标识、拼接定位或改写摘录。

要针对某个知识点或来源增加题目，在「AI 生成」切换到「定向补题」，选知识点后可选中其下来源，也可逐个选择。生成结果的知识点和来源旁也提供「补题」按钮。设置本次合计 1–100 道，由 AI 分配适合的题型，或分别设置四类题型数量。多个来源之间分配的是这个合计数，不是每个来源各出一遍；优先覆盖题目较少的来源，同量时随机安排。单次最多选择 100 个来源。

已归纳的完整来源单独持久保存，包含分类、同源标记和原文快照，不依赖最近一次任务；迁移 011 会从已有全文梳理任务回填。尚未梳理过来源的旧题，需要先对原资料运行一次「按资料生成」。定向补题直接使用选中的来源，不再全文分析，原题库题及已创建试卷不变。模型同时看到该来源已有题目的题干、选项和标准答案；精确重复和答案冲突由服务端拦截，近似改写主要由模型对照已有题规避。

每次模型请求只生成一道，已完成请求的入库与进度同步保存；旧任务已成功的批次保留，只把失败或未完成题量拆成单题请求。自动重试后仍失败的请求进入问题列表，任务结束时弹出；管理员可仅重试失败及未处理部分，先失败后成功的来源也不会重做成功请求。全文梳理重试耗尽或模型配置、鉴权异常时明确结束，不伪造来源。模型少出、重复跳过或答案冲突时显示实际入库数与目标数，不无限补齐。每个来源增加再多候选，组卷时仍最多选一道；要在同一份卷中覆盖同一知识点的多道题，需要多个独立来源。

## 5. 从题库组成考试草稿

### 5.1 筛选口径

组卷只使用 `active` 题目，可按以下条件筛选：

- 知识点多选：多个值之间为「或」；不选表示不限。
- 难度单选：默认「全部」，可以限定简单、适中或困难。
- 资料库文件多选：命中任一所选文件的题目符合该条件；不选表示不限。该筛选不会裁掉题目自身的其他引用。
- 可选错题范围 `mistakeTopN`：先按上述条件筛选已启用题，再取达到 §6.4 易错标准且错误率排名前 N 的题。默认不启用；界面勾选后默认 N=50，可修改为正整数。N 限定候选题数量，不改变各题型题量。范围不足时明确提示，不混入普通题。
- 不同筛选维度之间为「且」。查询不得因一题引用多份资料而重复计数或重复抽取。

手动挑题列表还支持题型和题干关键词查询。知识点、题型、难度和资料筛选均由服务端执行。知识点筛选使用规范化后的完整值匹配，不做模糊合并。

多个知识点只是候选范围，不承诺每个知识点都抽到题。第一版不做逐知识点配额或自动均衡；管理员可以检查组卷结果，或手动挑题保证覆盖。

### 5.2 随机组卷：替换整份草稿试题

1. 先保存本场各题型数量，服务端从已保存 `blueprint` 读取目标，合计必须为 1～100。
2. 显示当前筛选下各题型可用的独立考点数、所需数量及跨题型同源互斥后的缺口，另返回总 `groupCount`。
3. 点击「从题库组卷」时携带场次 `expectedVersion` 和筛选条件。若已有试题，确认提示明确说明将替换本场全部试题；筛选和查看数量不会修改试卷。
4. 在一个事务内重新检查场次状态、版本、活动任务和候选题，以题型名额和考点组做二分匹配，一组跨题型最多一道。匹配允许重新分配先前名额，避免逐题型贪心造成假缺题。普通场次随机排序候选；滚动场次优先未使用或最久未使用的组，同优先级随机。
5. 任一题型不足则整次失败，返回各题型的所需、可用及缺少数量。不会重复凑题、少出题、借用其他题型、放宽难度或自动调用 AI。
6. 顺序按 `QUESTION_TYPES` 的单选、多选、判断、填空排列，各题型内部使用本次随机抽取后的顺序。复制为新场次题目，服务端重新配分，提交后刷新完整场次。

题量不足时，界面保留筛选与旧试题，可调整题数、范围或去题库补题。普通场次再次随机组卷可能重复使用其他考试的题；滚动场次优先轮换，但不承诺固定天数完全不重复。

### 5.3 手动挑题：追加到现有试卷

- 选择器中预览完整题目，跨分页保留已选题目 ID 和版本；默认只显示已启用题。
- 已由同一题库题导入本场的项目置灰并标记「已添加」，不允许同场添加其第二个版本。
- 确认时携带场次版本及每个已选题目的版本，服务端重新读取，不能提交浏览器提供的答案、分值或来源冒充题库记录。
- 若题目已编辑、停用或删除，拒绝本次添加并指出项目，不使用旧预览内容或静默跳过。
- 追加后总题数不能超过 100；不能新增与本场既有试题 `contentKey` 相同的题目，也不能追加同源组的第二道题。选择器标记同源已选，服务端最终校验；只检查本次新增造成的重复，不顺手清理原有试题。
- 保留既有题目的 ID 和相对顺序，新题按选择顺序追加。服务端按最终整卷重新配分，并把 `blueprint` 的四类数量更新为实际题数；保留其 `difficulty` 和 `extraPrompt`。
- 整批添加在一个事务中完成，失败不留下部分新题或新资料。

### 5.4 场次锁定与页面未保存内容

两种组卷操作都只允许无答卷、无本场活动 AI 任务的可编辑草稿。事务内检查状态和 `expectedVersion`，成功时场次 `version` 只增加一次。已发布、已锁定或版本过期时不写入。

有未保存的题目、题数或其他会影响组卷的表单时，先要求保存或明确放弃，再提交组卷请求；请求期间禁用冲突操作。不能刷新场次后静默丢弃编辑器中的本地修改。沿用现有题目草稿保留和冲突提示机制，不另建全局状态管理。

组卷方式只是选择本次操作，不增加考试类型字段，也不在切换入口时清空资料、试题或出题设定。

## 6. 资料引用和历史试卷必须独立

### 6.1 题库引用指向资料库

现有 `SourceRef` 为 `{ documentId, locator, quote }`，其中 `documentId` 只在一个场次内有意义。题库使用独立结构：

```ts
interface BankSourceRef {
  libraryFileId: string
  locator: string
  quote: string
}
```

保存与启用时确认库文件存在且已解析、定位段存在，摘录按现有 `normalizeDocText` 和摘录长度限制校验，必须命中该定位段。复用归一化和题型结构规则，不取消原有场次归属校验，也不把 `libraryFileId` 塞进 `documentId` 冒充有效场次引用。

### 6.2 组卷时自动挂载来源并转换 ID

两种题库组卷操作共用以下过程，并与试题写入处于同一个短事务中：

1. 收集本次选中题目的全部资料库文件 ID。
2. 本场已有相同 `libraryFileId` 的资料时复用其 `documents.id`；其余文件按资料库挂载规则复制元数据和定位段，不复制物理文件。
3. 检查本场最终资料仍满足最多 5 份、正文合计最多 40000 字符。保留已有资料，不自动移除旧卷未再引用的资料。
4. 把每条 `BankSourceRef.libraryFileId` 映射为本场的 `documentId`，生成普通 `SourceRef`，再通过现有 `validateSourceRefs`。
5. 复制题干、选项、答案、解析、引用到 `questions`，保留本次来源题库 ID 和版本，并按本场顺序计算分值。

不能通过前端依次「添加资料 → 写题目」来实现，也不能在外层事务里直接嵌套调用现有 `attachLibraryFilesToExam` 和 `saveQuestions`：当前 `withTransaction` 不支持嵌套。按需要提取小范围的事务内校验和写入函数，保留原接口行为。

来源数量或字数超限时整次组卷失败，展示当前数量、新增数量和上限，要求缩小资料范围或先移除无用资料。随机选题后也必须检查这些限制，不反复重抽或隐式丢弃引用以凑出一份卷。

题库来源只用于记录从哪里复制。之后在本场编辑题目不会回写题库；记录的来源版本也不表示本场内容仍与原题完全一致。题库题删除后，场次试题、已复制定位段、评分和结果继续正常工作。

### 6.3 资料库删除保护

资料库文件被任何场次资料或任何状态的题库题引用时均不能删除。删除前在事务内检查两类引用，并保留外键约束。题库停用不释放来源，管理员需先删除该题或改换引用。

- 保留原 `LIBRARY_FILE_IN_USE` 错误码和 `details.exams`，追加 `details.questionBankItems`（最多 5 个，含 ID 和题干摘要）及 `questionBankCount`。
- 资料库页面说明被哪些场次或题库题引用，并提供题库定位入口。
- 原 `LibraryFileDTO.usageCount` 仍表示引用场次数，不混入题目数；新增 `questionBankCount` 展示题库引用题数，按不同题目计数，不按引用条数计数。
- 删除来源场次不会删除题库题或资料库拥有的文件；沿用资料库对旧路径原件的保留规则。
- 不提供原地替换资料文件。资料更新作为新库文件处理，管理员补新题、更新引用或停用旧题；不自动判断内容是否过期。

### 6.4 易错题：按实际作答人数与未满分率自动标记

管理端「错题集」是题库中筛选出的团队易错题集合，不另存一份试题。管理员可以看到哪些题很多人未能答对，再判断是重点尚未掌握，还是题目、答案或解析需要修订。考生端「我的错题」独立按本人历次已交卷且已公开答案的未满分记录查询，不受本节的团队统计门槛限制。

#### 6.4.1 只统计同一道题的可比作答

统计来源包括：

- `questions.source_bank_item_id` 指向该题库题的场次试题。
- 该题库题保存的 `origin_exam_id + origin_question_id` 明确指向的来源试题。因此，从已经考过的试卷入库的题目，可以直接利用该来源题目的历史作答，无须改写来源试卷。

同一场次题目同时命中两个条件时只取一次。不按相似题干自动关联其他历史试题，也不回填未明确关联的场次。

来源 ID 只证明出处，不证明试题从未被修改。参与统计前，必须把场次副本与题库当前题目进行**考查内容比较**：

- 比较 `type`、归一化后的 `stem`、按现有固定顺序排列的选项 ID 与文本，以及完整 `answerDefinition`。
- 题干和选项文本使用 §3.3 的 NFC、首尾空白与连续空白归一化；正确选项集合排序后比较。
- 填空题按空位顺序比较空位 ID 和可接受答案集合；答案使用统一 `normalizeBlank` 规则后去重、排序比较，旧 `caseSensitive` 标志不参与比较，不能只比较空位数量。
- 不比较分值、位置、解析、资料引用、知识点、难度、启停状态或并发版本。这些字段变化不改变本题的作答和评分定义。

可以将上述字段投影为稳定结构后直接比较，不存哈希或新增内容版本体系。§3.3 的 `contentKey` 不包含答案，不能单独作为统计可比条件；`source_bank_item_version` 也不能单独用于筛选，因为启用、停用和分类调整同样会增加版本。

题干、选项或答案实际改动后，旧内容的作答不再计入当前题目；场次副本单独改题也按同样规则排除。只改解析、出处或分类时保留可比统计。旧场次的分数、统计和题目仍保持原样，不为生成题库指标重新判分。

#### 6.4.2 一人只计一次，未作答单独列出

- 只读取 `attempts.status = submitted` 的答卷，包括手动和截止交卷；不读取进行中输入。
- 按当前系统身份 `name_key` 对同一题库题的可比作答去重，不能把同一人参加多场算成多个人。
- 同一人有多次已交卷且实际作答的记录时，取最早一次，按 `submitted_at ASC, attempt.id ASC, question.id ASC` 确定稳定顺序，避免反复练习后的结果覆盖首次表现。
- 同一人只有未作答记录时，计入 `unansweredCount`；有实际作答记录时使用其最早已作答记录，不再重复计入未作答人数。
- 是否作答使用现有空答案规则判断，不把「得 0 分」当成「未作答」。未作答不进入错误率分母；多空题只要实际填写过内容就属于已作答，未完成部分按现有评分处理。
- 每人的结果使用该场次题目的 `overrideScoreUnits ?? autoScoreUnits`，与该题自己的 `maxScoreUnits` 比较；不能直接跨场比较分值大小，也不重新运行评分。

题库接口中的统计字段：

| 字段 | 含义 |
| --- | --- |
| `sampleSize` | 去重后的已作答人数，即错误率分母 |
| `correctCount` | 最终得满分人数 |
| `partialCount` | 最终分数大于 0 且未满分人数 |
| `zeroCount` | 已作答但最终得 0 分人数 |
| `errorCount` | `partialCount + zeroCount`，即已作答但未满分人数 |
| `unansweredCount` | 仅有未作答记录的去重人数，不包含在 `sampleSize` 中 |
| `errorRate` | `errorCount / sampleSize`，0～1；无已作答样本时为 `null` |
| `isErrorProne` | 是否达到下述自动标记条件 |

始终满足 `sampleSize = correctCount + partialCount + zeroCount`。这里的「错误率」指未满分比例，包含填空部分正确或人工复核后的部分得分；界面在错误率列旁明确说明「按未满分统计，含部分得分，不含未作答」。现有场次统计口径不因本功能而改变。

#### 6.4.3 初始标记条件

第一版采用两个共享常量，不增加设置页面：

```ts
const BANK_MISTAKE_MIN_SAMPLE = 10
const BANK_MISTAKE_RATE_THRESHOLD = 0.5
```

`sampleSize >= 10` 且未经显示舍入的 `errorRate >= 0.5` 时，自动显示「易错」。例如 20 人实际作答、12 人未得满分，错误率为 60%，达到标记条件。只有 2 人作答且全部出错时，显示「样本不足：2 人」，不标易错。

人数不足时仍展示真实人数和已有错误率；无已作答样本时显示「暂无作答数据」，错误率为「—」，不能显示为 0%。部分得分、0 分和仅未作答人数在详情中分别展示。

标记是查询时派生的结果，不写入题目启停状态，不增加人工清除标记操作。新增答卷或管理员复核改分后，下次读取自然更新；不增加后台统计任务、缓存表或交卷后的计数写入。达到阈值不会自动停用题目、修改难度或调用 AI；只有管理员主动选择错题范围时才限制组卷候选。

#### 6.4.4 查询与界面

- 题库列表和详情返回 `mistakeStats`，结构使用上表字段；启用和停用题均可展示各自当前内容的统计。
- 列表增加已作答人数、错误率与「易错」标记；详情补充满分、部分得分、0 分及仅未作答人数，并说明同一人取最早已作答记录。
- 管理页保留「仅看易错题」筛选；菜单新增独立「错题集」页面 `/admin/mistakes`，只显示已启用易错题，显示排名、错误率、错误人数与作答人数，可筛选、查看和编辑。
- 错题集和易错筛选按未舍入的错误率降序、作答人数降序、ID 升序排列，先排序再分页，翻页延续排名。普通随机组卷、滚动出题及手动选择器提供「使用错题集」和前 N 道范围；组卷预览与实际写入共用候选计算。滚动规则保存范围，每日运行读取最新统计，不保存一份固定错题副本。
- 统计和易错筛选由服务端执行。筛选应先计算候选题的指标，再过滤和分页，不能只在当前页找易错题；列表总数也使用筛选后的数量。
- 按候选题批量读取关联试题和已交卷结果，统一完成可比性判断与人数去重，避免每题单独发请求或逐个查询。只读取必要字段，不返回考生名单和原始作答。
- 题库指标只供管理员查看，不增加考生接口，也不改变 `after_exam` 的答案公开规则。标记用于提示管理员优先检查当前题目和对应培训重点。

## 7. 数据模型与兼容要求

使用现有 SQLite 和迁移机制，只追加迁移。题库表由 `004-question-bank` 创建，直接启用规则由 `008-bank-direct-activation` 补充，`009-rolling-question-bank` 增加同源分组、组快照、题库生成任务及每日规则和记录；不改已执行迁移，不删库重建，不自动把历史试卷全部入库。

### 7.1 新增两张表

**`question_bank_items`**

| 字段 | 类型与含义 |
| --- | --- |
| `id` | TEXT 主键，服务端 UUID |
| `version` | INTEGER NOT NULL，初始 1 |
| `status` | TEXT，保存时显式写入 active；disabled 为主动停用。保留旧 draft 枚举及表默认值，迁移将旧 draft 转为 active |
| `type` | TEXT，现有四类题型，CHECK 约束 |
| `knowledge_point` | TEXT NOT NULL，规范化后的主要知识点 |
| `source_group` | TEXT NOT NULL，默认空串；同源考点名称 |
| `difficulty` | TEXT，`easy / normal / hard`，CHECK 约束 |
| `stem`、`options_json`、`answer_definition_json`、`explanation` | 与场次题目相同的内容结构，无 `max_score_units` |
| `content_key` | TEXT NOT NULL UNIQUE，按 §3.3 计算 |
| `origin_exam_id`、`origin_question_id` | TEXT 可空，仅记录历史来源 ID，不设指向场次或场次题目的外键，避免阻止来源删除 |
| `reviewed_by`、`reviewed_at` | 保留旧字段兼容历史数据，不再作为保存、启用或组卷的条件 |
| `created_at`、`updated_at` | INTEGER，UTC 毫秒 |

**`question_bank_sources`**

| 字段 | 类型与含义 |
| --- | --- |
| `bank_item_id` | TEXT，外键到题库题，`ON DELETE CASCADE` |
| `position` | INTEGER，从 1 递增，与 `bank_item_id` 组成主键 |
| `library_file_id` | TEXT NOT NULL，外键到 `library_files`，`ON DELETE RESTRICT` |
| `locator`、`quote` | TEXT NOT NULL，定位与摘录 |

引用只保存在引用表，不再维护另一份题库 `source_refs_json`。详情查询按 `position` 组装 `BankSourceRef[]`；修改题目时在同一事务中整体替换引用。

为状态、题型、知识点和难度筛选建立适量索引，并为 `question_bank_sources.library_file_id`、列表的 `updated_at / id` 排序建立索引。不引入 ORM、搜索服务或新依赖。易错指标直接聚合已有答卷与场次副本，不新增统计表或错误率列。

### 7.2 场次题目增加来源信息

`questions` 追加可空 `source_bank_item_id` 和 `source_bank_item_version`，为 `source_bank_item_id` 建立索引。二者成对为空或成对有值，仅表示本题最初从哪个题库版本复制，不设指向题库题的外键，避免阻止源题删除。另存 `source_bank_group_key` 快照供同源互斥与轮换，源题删除不丢该信息。旧的题库副本按原题库 ID 回填独立组，未关联题库的旧题仍为空。

管理员 `QuestionAdminDTO` 增加：

```ts
bankOrigin: { itemId: string; version: number; deleted: boolean; groupKey?: string | null } | null
```

现有整体保存试题仍接受原 `QuestionDraftInput`，不要求旧调用方增加题库字段。服务端在删除重写前，按本场既有题目 ID 保留其来源信息；新题不允许客户端自行指定来源。题库导入由专用服务写入来源。普通重排、改分值或本场编辑不丢失来源记录。

同步调整 `QuestionRow`、查询列、插入输入、管理员 DTO 和所有相关调用。考生作答、结果和评分只读场次副本，不查询题库；不得因此把题库答案或来源管理接口开放给考生。

## 8. 管理员接口契约

全部沿用 `/api` 前缀、`{ data }` 成功外壳和 `{ error: { code, message, details? } }` 错误结构。服务端检查管理员权限、同源写请求，响应 `no-store`。题库详情中的答案和解析只能经管理员接口返回。

### 8.1 类型与列表约定

在 `shared/types/question-bank.ts` 中定义题库 DTO、`BankSourceRef`、`BankMistakeStats`、列表筛选、组卷请求和生成任务。列表及详情包含只读统计、`sourceGroup` 和服务端计算的 `sourceGroupKey`。内容输入使用资料库引用，另含 `knowledgePoint`、`difficulty` 及可选 `sourceGroup`；省略分组的新题视为独立题，旧调用保存时保留已有分组。状态、版本、来源场次和统计由服务端管理，不接受内容输入覆盖。

列表每页默认 20、上限 500，采用现有分页参数解析规则；普通列表按 `updatedAt DESC, id DESC` 稳定排序，易错筛选或指定错题范围时按 §6.4 的排名排序。返回题干摘要、分类、状态、版本、来源文件名称、时间和易错统计；详情才返回完整题目内容。关键词对题干做参数化 LIKE 查询，转义 `%` 和 `_`。

列表参数：`page`、`pageSize`、`query`、`type`、`status`、`difficulty`、`errorProneOnly`、`mistakeTopN`，以及可重复的 `knowledgePoint`、`libraryFileId`。`errorProneOnly=true` 时只返回达到 §6.4 阈值的题，省略或 `false` 时不限；该参数只用于管理查询。可选 `mistakeTopN` 为正安全整数，查询参数为整数文本、JSON 体为数字；列表和组卷共用该字段，先过滤并排名，再取前 N 项，最后分页。未填状态时题库管理页显示所有状态；错题集和组卷选择器固定传 `active`，写入时仍由服务端重新检查。非法输入返回 `VALIDATION_FAILED`。

### 8.2 接口清单

以下路径均位于 `/api/admin` 下：

| 方法与路径 | 输入与成功结果 |
| --- | --- |
| `GET /question-bank` | 按 §8.1 查询，返回分页摘要列表 |
| `GET /question-bank/knowledge-points` | 返回现有题目的知识点去重排序列表，供输入及筛选选择，不建立分类管理功能 |
| `GET /question-bank/:itemId` | 返回完整题目、分组、引用、来源、版本及当前内容的 `mistakeStats` |
| `GET /question-bank/source-groups` | 已有同源考点名称列表 |
| `POST /question-bank` | 完整题目内容，创建已启用题；201 返回详情 |
| `PUT /question-bank/:itemId` | `{ expectedVersion, question }`，保存后保持启用或主动停用状态，返回详情 |
| `POST /question-bank/:itemId/enable` | `{ expectedVersion }`，校验内容后重新启用，返回详情 |
| `POST /question-bank/:itemId/disable` | `{ expectedVersion }`，已启用题改为停用，返回详情 |
| `DELETE /question-bank/:itemId?expectedVersion=` | 直接删除启用或停用题，返回 `{ ok: true }` |
| `POST /question-bank/batch-delete` | `{ items: [{ itemId, expectedVersion }] }`，1–500 项，全批原子删除，返回 `deletedCount` |
| `POST /question-bank/generate` | `{ libraryFileIds, difficulty, extraPrompt }`，201 返回题库生成任务；使用现有模型设置，不要求题量或考点数量 |
| `GET /question-bank/generation` | 当前或最近任务及输入、来源处理进度、`generatedCount`、实际入库数 `createdCount`、重复、答案冲突及未解决错误，无任务时为 null；逐请求入库，运行中和最终失败的任务也可有已入库题目 |
| `POST /exams/:id/questions/to-bank` | `{ expectedExamVersion, items: [{ questionId, knowledgePoint, difficulty }] }`；全批成功后 201 返回新题详情列表，均为已启用 |
| `GET /exams/:id/question-bank-availability` | 返回 `examVersion`、`groupCount` 和 `required / available / missing`；available 为该题型可用组数，missing 为跨题型互斥匹配后的缺口；不足仍为正常查询，不修改数据 |
| `POST /exams/:id/questions/from-bank` | 使用下列联合请求类型；成功返回最新 `ExamAdminDTO`，包含全部资料、题目、版本及发布预检 |

```ts
type BankApplyRequest =
  | {
      expectedVersion: number
      mode: 'random'
      filters: {
        knowledgePoints?: string[]
        libraryFileIds?: string[]
        difficulty?: Difficulty
        mistakeTopN?: number
      }
    }
  | {
      expectedVersion: number
      mode: 'manual'
      items: Array<{ itemId: string; expectedVersion: number }>
    }
```

随机模式只从已保存 `blueprint` 读取数量，不能由请求额外传一套数量。手动模式的 `items` 非空、ID 不重复、最多 100 项。批量入库的 `questionId` 同样必须非空且不重复。随机模式的候选题及状态在写事务内读取；手动模式额外检查每题版本，防止预览后题目已变。

组卷和入库失败均整体回滚。预览不代替最终事务校验。只有管理员主动发起 `/question-bank/generate` 才调用模型，其他题库接口不会因数量不足自动补题。滚动接口见 [每日规则说明](rolling-bank-plan.md)。

### 8.3 新增错误码

并入 `shared/types/common.ts` 和 `API_ERROR_STATUS`：

| code | HTTP | 含义及界面动作 |
| --- | --- | --- |
| `QUESTION_BANK_DUPLICATE` | 409 | 题库存在相同内容键；返回冲突输入序号、已有题目 ID 和状态，允许查看已有题 |
| `QUESTION_BANK_STATE_CONFLICT` | 409 | 当前状态不允许启用、停用或删除等操作；刷新状态后处理 |
| `QUESTION_BANK_ITEM_UNAVAILABLE` | 409 | 手动选中的题目未启用或已删除；返回项目 ID 和原因，保留其他选择 |
| `QUESTION_BANK_ALREADY_ADDED` | 409 | 本次手动添加与现有场次题库来源或内容重复；返回冲突项目 |
| `QUESTION_BANK_SHORTAGE` | 422 | 按题型返回 `required / available / missing`，调整范围或题数 |

继续复用 `VERSION_CONFLICT`、`EXAM_LOCKED`、`EXAM_HAS_ATTEMPTS`、`EXAM_HAS_ACTIVE_JOB`、`QUESTION_SET_INVALID`、`VALIDATION_FAILED`、`FILE_LIMIT_EXCEEDED`、`DOCUMENT_CHARS_EXCEEDED` 和 `LIBRARY_FILE_IN_USE`。题库版本冲突需说明冲突的题目 ID 和当前版本；资料超限需补齐当前值、新增值和上限，不能只显示「操作失败」。
