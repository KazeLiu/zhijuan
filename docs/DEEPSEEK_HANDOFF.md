# 给 DeepSeek 的开发交接

## 可直接发送的任务

请在 `D:\code\zhijuan` 实现「知卷」首版。先读取适用的 AGENTS.md、README.md 和 `docs/design.md`，然后按照设计文档完成开发。

`docs/design.md`（当前 v0.3）是本次实现和后续代码检查的业务依据。当前已经有项目目录和文档，尚无 Nuxt 应用代码。你的任务是实现真实可用的完整流程，不是重新讨论技术栈、只画静态页面或用假数据演示。

目标运行环境为 Windows 内网服务器：依赖安装与构建在目标机执行，构建产物是 `.output` 目录，由 nginx 反向代理到本机 Node 端口；不要采用需要本地编译工具链的原生依赖，也不要把纯静态 `dist` 当作完成部署。

### 你负责的范围

1. 建立 Nuxt 4 + Vue 3 + TypeScript + Element Plus 全栈项目，使用 SQLite 和私有本地资料存储。
2. 接通姓名登录、服务端管理权限、管理员模型配置与模型列表刷新。
3. 实现文件上传与正文预览、AI 生成候选题并按题型随机抽题组卷、管理员编辑审核、精确配分和发布时间冲突检查。
4. 实现用户逐题作答、计时、服务端保存、续答、手动交卷与后台截止交卷。
5. 实现交卷即时判分、人工复核与完整结果页。
6. 实现每场考试的答案公开选项：交卷后立即公开 / 本场结束后公开，**默认立即公开**。服务端按条件裁剪数据，不能只在前端隐藏。
7. 实现场次汇总与本场 Excel 导出，补齐真实运行所需的迁移、锁文件、启动脚本与使用说明。

### 可以自行决定

- 符合设计的组件拆分、函数名称、SQL 查询实现和实际需要的成熟文件解析/SQLite 依赖。
- 在既定页面和交互方向下优化布局、间距、表单反馈和代码组织。
- 修复本次功能所必需的相邻调用问题，无须把低风险内部实现细节逐项交给用户选择。

### 不可以擅自改动

- 不把 Nuxt 换成 Next.js、纯 Vite 项目或其他框架，不换掉 Element Plus，不单独搭建第二套后端。
- 不增加密码、注册、验证码、考生名单、复杂防作弊、随机题库、OCR、向量服务或分布式任务平台。
- 不改变姓名身份模型、每场一次答题、固定同卷、时间区间不重叠、服务端截止、满分 100 分、默认立即公开等业务规则。
- 不让客户端计算最终成绩、决定管理员身份、读取已存 API Key 或直接调用模型；管理员录入新 Key 时只单向提交。不得向考生返回尚未公开的答案及评分信息。
- 不把数据只存在内存或浏览器；不使用随机分数、假模型列表、固定样题或 Mock 接口充当已完成的功能。
- 不把 AI 异常静默变成 0 分，不自动重复付费调用，不用无限重试或换模型掩盖错误。
- 不重写设计文档以适应实现缺口；若确有冲突，指出具体章节、原因及影响，交由用户决定。
- 不覆盖用户新增的无关文件，不读取、打印、拷贝现有凭据，不把真实资料、Key、数据库、日志或构建产物加入源码仓库。
- 不主动新增/修改/运行测试，不引入测试框架或 TDD；不主动启动应用、浏览器、构建、打包、调用真实模型、提交、推送或部署。这些操作需要用户另行明确要求。

### 实现顺序

按完整依赖顺序推进，不要求为每一步创建额外的计划文件：

1. 框架、数据库迁移、会话和服务端权限。
2. 模型设置、资料提取、考试草稿与真实 AI 出题。
3. 题目审核、配分、发布与时间锁定。
4. 答题、版本保存、交卷、截止补处理。
5. 判分、人工复核、公开规则与结果入口。
6. 场次汇总、错误恢复、使用说明和基本代码自查。

编写代码后，通过阅读代码、核对调用关系和查看差异自查。设计中的验收清单是用户试用与后续检查的依据，不代表你有运行测试的授权。

### 完成交接

结束时说明以下内容即可，不创建重复的设计文档或泛泛的「全部通过」报告：

- 已实现的完整入口和实际使用方式。
- 管理员名称配置位置、模型设置入口、数据存放位置。
- 实际执行过的安装或其他命令，哪些运行结果有证据，哪些尚未确认。
- 真实未完成项、具体影响和已知 bug；不得把缺功能写成可选优化。

保留必要的源码、依赖锁文件和迁移，便于用户试用后交给 Codex 检查与修复。不要自行提交或推送。
