# 知卷（ZhiJuan）

面向内网培训与知识自测的 AI 在线答题系统，支持资料出题、考试管理、自动判分与成绩导出。

上传培训资料，由 AI 生成试题，管理员检查编辑后发布考试，也可配置每天从题库自动组卷并发布；参与者输入姓名即可选择场次答题，交卷后查看成绩，并按场次设置查看答案与解析。资料、试卷和答卷保存在自部署服务中，适合团队内部培训和日常知识自测。

## 主要功能

### 管理端

- **资料库**：上传、搜索、预览和复用文字版 PDF、DOCX、TXT、Markdown；场次内上传的资料自动归档到资料库。
- **题库**：AI 通读资料、归纳知识点与完整来源，再逐来源生成多道题；可按已有知识点或来源定向补题，设置本次新增题量，支持中断后继续。也可人工录题或从场次入库，支持编辑、启停、多选删除和错题筛选，同源题目每卷最多选一道。
- **错题集**：按各场实际交卷人次统计错误率，有错误记录即收录并排序，无最低人数限制；普通组卷与滚动出题可限定从错误率排名前 N 的题目中选题。
- **滚动出题**：保存每日规则后自动从题库组卷并发布，优先使用未用或最久未用的考点，与手动场次并存。
- **AI 出题**：按单选、多选、判断、填空分别设置题量，生成候选题并随机抽取为本场固定试卷，满分 100 分。
- **试卷编辑**：发布前预览、编辑题目、答案、解析与资料引用；发布后锁定试题和评分标准。
- **场次管理**：设置名称、时区与开放起止时间，允许同时开放多场，由考生自行选择；支持暂停、继续和提前结束。答案与解析可在交卷后立即公开，或本场结束后公开，默认立即公开。
- **成绩管理**：查看场次统计、个人答卷，导出本场 Excel 成绩表；支持逐题复核改分，记录原因与改分前后的分值。
- **填空答案纠错**：按题目和空位归并错误写法，管理员批量认可同义答案，预览分数变化后重判本场；保留原始作答和人工复核分，可选择同步别名到题库。见 [操作说明](docs/blank-answer-correction.md)。
- **模型配置**：在管理页面设置模型服务地址、API Key 和模型，刷新模型列表并选择思考强度。

### 答题端

- **姓名入口**：无须注册或密码，输入姓名后查看考试安排，点击「开始答题」才创建答卷并计时。
- **逐题作答**：提供答题进度、题号导航和已用时间，自动保存答案，刷新后可继续作答。
- **自动判分**：四类题型均为客观题，交卷后立即出分；开放时间结束时，按最后保存的答案自动交卷。
- **填空规则**：统一忽略大小写和两端空白，保留内部空格、标点与单位；同义写法由管理员确认后加入可接受答案。
- **答题复盘**：查看本人历次成绩、作答记录，以及已到公开时间的正确答案和解析；成绩详情默认只看错题，取消勾选后显示全部题目。
- **我的错题**：汇总当前登录姓名历次考试中已公开答案的未满分题目，包含部分得分和未作答，可查看本人答案、正确答案、解析及来源考试；无需达到团队错题集的人数或错误率门槛。

## 使用边界

- **仅用于可信内网的培训和知识自测**。身份只依赖姓名，知道管理员名称即可使用管理员身份，知道他人姓名即可查看或继续其答卷；请勿直接开放到公网，成绩不作为考核、认证、合规举证或奖惩依据。
- 同一姓名每场只有一次答题记录；重名时使用「部门＋姓名」区分。管理员参加考试时，需要换用不在管理员名单内的姓名。
- 同一场所有参与者使用相同题目和顺序。每场 1～100 题，按总题数等分 100 分，使用整数计分单位处理尾差；多选漏选、错选均不得分，填空按每个空的可接受答案匹配并按空给分。
- 开放窗口内随到随考，显示已用时间，不设独立个人限时；场次截止时间以服务端为准。
- 文件解析支持文字版 PDF、DOCX、UTF-8 TXT 和 Markdown，不包含扫描件 OCR。

## 技术栈

- **全栈框架**：Nuxt 4、Vue 3、TypeScript、Nitro。
- **界面组件**：Element Plus 2.x。
- **数据存储**：Node.js 内置 `node:sqlite` 与私有本地文件，无须外部数据库或 C++ 编译工具链。
- **文档与导出**：`unpdf`、`mammoth`、`exceljs`。
- **模型接口**：兼容 Chat Completions 的模型服务，使用 `/models` 获取模型列表、`/chat/completions` 生成试题。

## 快速开始

以下为原生 Node.js 开发方式，环境要求 **Node.js ≥ 22.19.0**、**pnpm 9.12.1**。只部署使用时，可直接查看下方 Docker Compose 部分，无须在宿主机安装这两个工具。

在项目根目录执行（PowerShell）：

```powershell
pnpm install
Copy-Item .env.example .env
pnpm dev
```

首次运行时复制配置模板并按需修改；已有 `.env` 时跳过复制。macOS / Linux 使用 `cp .env.example .env`。

打开 [http://localhost:4310](http://localhost:4310)，首次可输入默认管理员姓名 `管理员` 进入管理端。

### 第一次用 AI 发布考试

1. 在「模型设置」填写 Base URL，按模型服务要求填写 API Key，刷新列表并选择模型。
2. 在资料库上传资料，或在新建考试时直接上传。
3. 设置各题型题量，启动 AI 出题，核对题目、答案、解析及资料引用。
4. 设置考试开放时间和答案公开策略，确认后发布；多场考试可以同时开放。
5. 参与者输入自己的姓名，在开放时间内开始答题；管理员在场次结果中查看和导出成绩。

新建场次默认使用 `Asia/Shanghai` 时区，名称为当天日期加「测试」（例如 `2026年10月26日 测试`），开放时间为当天 00:00 至次日 00:00。名称、时区和时间均可修改，同一时段可安排多个场次。

Base URL 填写模型服务的 API 前缀，例如 `http://your-model-host:8000/v1`，不要填写完整的 `/chat/completions` 路径。出题会将选用资料的文本发送至所配置的模型服务；资料不能离开内网时，请使用内网模型。

### 从题库发布考试

1. 在「题库 → AI 生成 → 按资料生成」选择资料和难度，可填写补充要求。AI 通读全文、归纳知识点与完整来源，再按来源逐题生成，每次只请求一道，校验入库后再出下一道；不需要填写考点数量，进度显示来源与实际题数。也可人工新增，或从场次勾选已保存题目入库。
2. 入库后即可组卷，不需要审核。知识点优先匹配已有分类，也可手动调整；停用题不参与组卷，重新启用后恢复可用。
3. 新建考试草稿，保存各题型题数。在「组卷与出题」选择知识点、难度或资料，查看可用数量后随机组卷；也可手动挑题追加。随机组卷替换整份试卷，手动挑题保留旧题并重新配分。
4. 核对本场试题，设置开放时间后发布。题库后续编辑、停用或删除，不影响已经复制到考试中的题目。

人工维护与题库组卷不需要配置模型；只有主动发起 AI 生成或补题任务才调用模型，不会自动补足缺题。组卷时来源资料超限、独立考点不足或版本冲突，整次组卷不写入。AI 题库请求默认最多尝试 3 次，仍失败则记录原因并继续后面的请求及来源，结束后弹出问题列表；可只重试失败部分，已入库题目保留。点击题干可直接编辑；多选后可直接删除，旧试卷与答卷不变。

同一资料中同名「同源考点」的题目属于一组，随机组卷跨题型每组最多选一道，手动挑题也执行此约束。系统为完整来源的所有题目统一附加分组；未归组的旧题默认独立，可在编辑页选择同名考点合并，不能仅因同一文件或段落就视为重复。

### 使用带 ★ 和填空标记的内部资料

在「按资料生成」将「资料规则」切换为「★ 与 <> 标记」，先点击「解析来源」查看层级和熟记继承，再生成题目。带子项的完整条目保留为同一来源；熟记内容中的 `<答案>` 由程序直接生成原文填空，普通内容只出判断和选择。后续在「定向补题」选择带「【标记】」的来源，复用原文结构。详见 [标记资料出题](docs/marked-document-exams.md)。

### 针对已有知识点补题

1. 打开「题库 → AI 生成 → 定向补题」，选择知识点，再勾选全部或部分来源；也可在生成结果的知识点或来源旁点击「补题」。
2. 设置本次合计题量，或分别设置各题型数量，例如单选 3 道、判断 2 道。数量是整个选中范围的合计，不是每个来源各出一遍。
3. 点击「开始补题」，沿用原文与同源分组，不重新分析全文；每次请求一道题，指定题型时仅发送对应题型的规则和示例。精确重复会跳过；同题但标准答案不同的结果不入库，页面展示新旧答案，原有题目不变。

来源会长期保留，不依赖最近一次任务。每次最多申请新增 100 道，实际数量不足时会显示目标、已入库数及原因，不强行凑题；失败可继续未完成部分。完整说明见 [题库 AI 生成与定向补题](docs/question-bank-generation.md)。

### 每天自动出一份试卷

1. 打开菜单「滚动出题」，设置名称、时区、每日开放时段、各题型数量、题库范围与答案公开策略。
2. 点击「检查可用题数」，查看同源互斥后的缺口；开启「每天自动组卷并发布」，保存规则。
3. 后台每 15 秒巡守，启用当天先生成当日试卷，之后每天按所选时区在零点生成；可以点击「立即生成今日试卷」开始试用。生成成功后在考试场次列表中正常管理，考生自行选场。
4. 题量或资料不符合条件时当天整次失败，页面显示原因；调整后点击「重试今日组卷」。不自动反复调用或创建半份试卷。

默认 20 题（单选 10、多选 4、判断 4、填空 2），开放时段为当天 00:00 至次日 00:00，首次需主动启用。修改规则不改变已生成试卷；暂停规则不结束已有场次。服务必须持续运行，重启只补当前尚未过期且未生成的一天，不补历史场次。

### 从错题集出卷

1. 打开菜单「错题集」，查看当前已启用错题的排名、错误率和错误／交卷人次，可按题型、知识点、难度及来源缩小范围，点击题干可编辑原题。
2. 在场次「从题库组卷」或「滚动出题」勾选「使用错题集」，设置错误率前 N 道作为候选范围，默认 50 道。先按知识点、难度和来源筛选，再排名截取；N 是候选题数量，试卷题量仍按各题型设置。
3. 检查可用题数后组卷。仍执行同源每卷最多一道；题型或独立来源不足时，扩大 N、调整题数或关闭错题集选项，不会自动混入普通题。手动挑题也可按相同条件浏览，确认后追加已选题。

题库的错误率为各场累计未满分人次除以累计交卷人次，包含部分得分和未作答零分，人工最终分优先。同一人参加不同场次时分别计入。8 人交卷、3 人错即显示 37.5% 并进入错题集，不要求满 10 人或错误率超过 50%。错误率相同时优先显示交卷人次更多的题，再按 ID 稳定排序；全部满分的题不进入错题集。详情区分满分、部分得分、作答零分和未作答零分。

首次使用题库版本时需重新启动服务，以自动应用追加的 `004-question-bank` 迁移；升级前按下文备份数据。历史试卷不会自动进入题库。

取消审核的版本追加 `008-bank-direct-activation` 迁移，重启后将旧的待审核题直接启用，已停用题保持停用。

同源分组、全文来源梳理及定向补题依次追加迁移 009、010、011，启动时自动升级；升级前先备份数据。审核接口已移除，重新启用使用 `/enable`，旧审核列仅保留历史数据，不再读取或返回。新流程的真实模型与页面效果待用户试用确认。

## 管理员与配置

| 配置项 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 管理员姓名名单 | `NUXT_ADMIN_NAMES` | `["管理员"]` | JSON 数组字符串；姓名与之全等即进入管理端（服务端判定） |
| 数据目录 | `NUXT_DATA_DIR` | `data` | SQLite 与上传资料的位置，相对路径以进程工作目录为基准 |
| 会话有效期 | `NUXT_SESSION_TTL_DAYS` | `7` | 天 |
| 会话 Cookie 名 | `NUXT_SESSION_COOKIE_NAME` | `zj_session` | |

示例：`NUXT_ADMIN_NAMES='["张三","李四"]'`。修改后重启进程生效。

**模型服务配置通过管理端 `/admin/settings` 维护**：Base URL、API Key、模型 ID 和思考强度保存在服务端数据库中。读取配置只返回 API Key 是否已配置，不回传明文；无须鉴权的内网模型可不填 Key。

填写接口地址和模型后，点击「测试连接」即可按当前表单发一条简短的对话请求，无须先保存。收到有效模型回复后显示连接成功和耗时；鉴权失败、超时、网络或响应格式错误会显示原因。测试最多等待 60 秒，不发送资料、不保存配置。Key 留空时沿用同一地址已保存的 Key；换地址测试需重新输入 Key，或勾选清除以无 Key 测试。

## 生产部署

### Docker Compose（推荐）

服务器安装 Docker 和 Compose v2 后，在仓库目录运行：

```sh
docker compose up -d --build
```

访问 `http://服务器内网IP:4310`，默认管理员姓名为 `管理员`。可在根目录 `.env` 中设置 `NUXT_ADMIN_NAMES` 和宿主机 `PORT`；容器内部固定使用 4310，数据保存在独立的命名卷中。无需另配数据库或 Redis。

首次构建需要联网；拿到离线镜像包后，按 [Ubuntu 24.04 离线部署说明](docs/docker-deployment.md) 加载镜像并启动，无须下载源码或安装 Node.js。不要执行 `docker compose down -v`，该命令会删除持久化数据。

管理员配置、模型地址、备份、从现有数据迁移和离线部署见 [Docker 部署说明](docs/docker-deployment.md)。已完成 `linux/amd64` 生产镜像构建，启动与模型连通性由部署环境确认。

### 原生 Node.js

部署形态为 **`.output` 目录 + 单个 Node.js 进程 + 私有数据目录**，可由 nginx 反向代理。需要持续运行服务进程，不能作为纯静态网站部署，也不支持多实例运行。

在项目根目录构建并启动（PowerShell）：

```powershell
pnpm build
$env:PORT = '4310'
node --env-file=.env .output/server/index.mjs
```

macOS / Linux 启动命令：

```bash
PORT=4310 node --env-file=.env .output/server/index.mjs
```

生产启动时通过 `--env-file` 显式加载 `.env`。将 nginx 转发至实际监听地址与端口；数据库和上传目录保持私有，不配置为静态资源目录。

开发访问优先使用 `http://localhost:4310`。若本机 `127.0.0.1:4310` 被占用，Nuxt 可能只监听 `[::1]:4310`，请根据实际监听地址配置反向代理。

## 数据位置与备份

```
data/
├─ db/zhijuan.sqlite       数据库（运行时另有 -wal / -shm）
└─ uploads/
   ├─ library/            资料库文件及新上传的场次资料
   └─ <examId>/           历史场次资料（保留原路径）
```

- `data/` **不进 Git**，也不由 HTTP 直接暴露；路径独立于构建产物，重建 `.output` 不会清库。
- **备份**：停止进程 → 整目录复制 `data/`（含 `-wal`/`-shm`）→ 完成。
- **恢复**：停止进程 → 用备份覆盖 `data/` → 启动进程。启动时会自动执行未应用的迁移，不需要人工跑 SQL。
- 换机器：把 `.output/` + `data/` + `.env` 一起搬到目标机，使用 Node.js 22.19.0 或更高版本，显式加载配置并保持数据目录指向不变。
- 数据库中包含模型凭据，备份也应按敏感数据保护；不要将 `.env`、数据库或上传资料提交到仓库。
