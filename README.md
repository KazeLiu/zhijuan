# 知卷（ZhiJuan）

面向可信内网的 AI 出题与在线答题系统。管理员上传资料生成试卷，用户输入姓名参加当前考试，系统即时判分并提供答题复盘与场次统计。

## 快速开始

环境要求：**Node.js ≥ 22.5**（使用内置 `node:sqlite`；实测 v22.19.0）、**pnpm 9**（实测 9.12.1）、Windows / macOS / Linux 均可。无需 C++ 编译工具链。

```bash
pnpm install          # 安装依赖（含 nuxt prepare 生成类型）
cp .env.example .env  # 首次运行：复制并按需修改
pnpm dev              # 开发服务器 http://localhost:4310
```

生产运行：

```bash
pnpm build            # 输出到 .output/
set PORT=4310 && node .output/server/index.mjs   # Windows
# PORT=4310 node .output/server/index.mjs        # bash
```

部署形态是 **`.output` 目录 + 一个 Node 进程**，由 nginx 反向代理到本机端口（不是纯静态 `dist`）。SQLite 与本地上传目录都在进程侧，不能只把静态产物丢给 nginx。

### 端口

开发与生产默认都用 **4310**。若本机 `127.0.0.1:4310` 被别的进程占用，Nuxt 可能只监听 `[::1]:4310` —— 请统一用 `http://localhost:4310` 访问。

## 管理员与配置

| 配置项 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 管理员姓名名单 | `NUXT_ADMIN_NAMES` | `["管理员"]` | JSON 数组字符串；姓名与之全等即进入管理端（服务端判定） |
| 数据目录 | `NUXT_DATA_DIR` | `data` | SQLite 与上传资料的位置，必须是相对于进程工作目录的路径 |
| 会话有效期 | `NUXT_SESSION_TTL_DAYS` | `7` | 天 |
| 会话 Cookie 名 | `NUXT_SESSION_COOKIE_NAME` | `zj_session` | |

示例：`NUXT_ADMIN_NAMES='["张三","李四"]'`。修改后重启进程生效。

**模型服务配置不进环境变量**：Base URL、API Key、模型 ID 存在数据库里，由管理端 `/admin/settings` 维护。API Key 只保存在服务端，任何接口只返回「是否已配置」，不回传明文。

> 管理员要参加考试时，请用另一个姓名进入考生端（管理端不提供以管理员身份作答的入口）。

## 数据位置与备份

```
data/
├─ db/zhijuan.sqlite       主库（运行时另有 -wal / -shm）
└─ uploads/<examId>/<documentId>.<ext>   私有资料原文
```

- `data/` **不进 Git**，也不由 HTTP 直接暴露；路径独立于构建产物，重建 `.output` 不会清库。
- **备份**：停止进程 → 整目录复制 `data/`（含 `-wal`/`-shm`）→ 完成。
- **恢复**：停止进程 → 用备份覆盖 `data/` → 启动进程。启动时会自动执行未应用的迁移，不需要人工跑 SQL。
- 换机器：把 `.output/` + `data/` + `.env` 一起搬，前提是目标机有 Node 22.5+。

## 技术选型

- Nuxt 4 + Vue 3 + TypeScript（单进程全栈，Nitro）
- Element Plus 2.x（UI 组件库，不可替换）
- SQLite：Node 内置 `node:sqlite`（无原生编译依赖，选型理由见 [ADR-001](docs/adr/ADR-001-sqlite-driver.md)）
- 私有本地文件存储：文字版 PDF / DOCX / TXT / Markdown
- Excel 导出：`exceljs`；PDF/DOCX 解析：`unpdf` / `mammoth`；日期：`dayjs`

## 功能需求

### 入口与身份

- 输入姓名进入系统，无须注册账号或输入密码。
- 管理员名称通过字符串数组配置，匹配后进入管理端。
- 姓名入口适用于可信内网；知道管理员名称的人可以使用管理员身份。
- 管理身份由服务端判定，API Key 只在服务端使用。

### 管理端

- 配置模型服务的 Base URL 和 API Key，刷新获取模型列表并选择模型。
- 上传资料，由 AI 生成单选题、多选题、判断题和填空题。
- 按题型分别设置题目数量，系统汇总总题数并自动等分分值，试卷满分为 100 分；候选题目按题型随机抽取一次，组成该场固定试卷。
- 新建场次默认名称为当天日期加「测试」（例如 `2026年10月26日 测试`），默认时区为 `Asia/Shanghai`；名称与时区均可修改。
- 设置每场考试的开放起止时间，不同考试的开放时间不能重叠；默认为场次时区当天 00:00 至次日 00:00。
- 每场设置答案与解析在交卷后立即公开或本场结束后公开，默认立即公开。
- 按考试场次汇总参与情况、成绩与个人答卷，并支持导出本场 Excel 成绩表。

### 用户端

- 输入姓名后查看考试安排，点击「开始答题」才创建答卷并计时；登录和刷新首页不会自动开始。
- 采用逐题翻页的答题表单，提供进度和计时器，交互参考多邻国的单题布局。
- 交卷后立即得到总分，可在本人记录中查看成绩、作答与解析；正确答案、对错和解析按本场公开策略展示。

## 实现建议

- AI 生成试卷后，管理员可以预览、编辑和确认，再发布考试。
- 同一场考试使用固定试卷，发布后锁定题目、分值和评分标准。
- 按总题数自动等分，使用整数计分单位处理尾差，确保合计 100 分。
- 自动保存答案与进度，刷新后继续答题；计时以服务端记录为准。
- 计时器显示已用时，考试开放时间结束时自动交卷；首版不设独立个人限时。
- 同一姓名在同一场考试中对应一次答题记录，未交卷时续答；重名使用部门加姓名区分。
- 四类题型全部为客观题，交卷事务内完成判分；填空题按每个空的可接受答案匹配，多空按空给分。
- 管理员可以对已交卷答卷逐题改分，需填写原因并保留改分前后记录，考生结果标注「人工复核」。
- 首版文件格式为文字版 PDF、DOCX、TXT 和 Markdown，不含扫描件与图片识别。

具体状态、失败处理和交付边界以 [系统设计](docs/design.md) 与 [实现契约](docs/impl-contract.md) 为准，不通过前端隐藏替代服务端权限或答案公开控制。
